## 跨动态库时的隐性破坏

即使你使用了正确的懒汉式：

```
static Singleton& getInstance() {
    static Singleton instance;  // ✅ 单例
    return instance;
}
```

如果这个头文件被 **不同的动态库 (.so/.dll)** 分别编译进去了，

> 那么每个动态库会有 **自己独立的静态存储区**，
>  各自生成一个 `instance`。

🔹 结果：

- **每个动态库都有独立单例实例**；
- 在宿主程序中调用时表现为**多实例**。

例如：

```
// main
A.so -> 使用 Singleton
B.so -> 使用 Singleton
```

此时 `A.so` 与 `B.so` 各有一份 `Singleton::instance`。

> ✅ 要想跨库保持唯一，要么：
>
> - 把单例定义放到**共享库中**（例如一个 `core.so` 导出接口），
> - 或在主程序中集中创建并传递引用。

## ⚠️ 错误写法示例（会出问题）

```
// ❌ 错误示例
// Singleton.h
class Singleton {
public:
    static Singleton instance; // 定义在头文件
};
Singleton Singleton::instance; // ❌定义在头文件，链接时重复定义
```

👉 这会导致：

```
multiple definition of `Singleton::instance'
```

每个 `.cpp` 文件都包含头文件时都会生成一个 `Singleton::instance` 实体。
