这是一个非常好的问题 👍——**在头文件中定义单例模式（Singleton）**，如果处理不当，很容易导致 **多重定义（multiple definition）** 或 **多个实例** 的问题。
 下面我会详细讲清楚几种常见做法、风险和正确写法。

------

## 🧩 问题背景：头文件定义会导致重复实例

假设你写了一个这样的单例：

```
// Singleton.h
#pragma once
#include <iostream>

class Singleton {
public:
    static Singleton& getInstance() {
        static Singleton instance; // 局部静态变量
        return instance;
    }

    void show() { std::cout << "Hello\n"; }

private:
    Singleton() = default;
    ~Singleton() = default;
};
```

然后在多个 `.cpp` 文件中都 `#include "Singleton.h"`。

👉 这段代码 **是没问题的！**

因为：

- `getInstance()` 是 **内联函数（inline）**，定义在头文件中不会产生多重定义。
- 局部静态变量 `static Singleton instance;` 在 C++11 之后有**线程安全保证**，并且在所有翻译单元中只有一个实例（由于函数是 inline）。

------

## ✅ 正确的写法（推荐）

```
// Singleton.h
#pragma once
#include <mutex>

class Singleton {
public:
    static Singleton& getInstance() {
        static Singleton instance;  // C++11 保证线程安全
        return instance;
    }

    void doSomething();

private:
    Singleton() = default;
    ~Singleton() = default;

    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;
};
// Singleton.cpp
#include "Singleton.h"
#include <iostream>

void Singleton::doSomething() {
    std::cout << "Working..." << std::endl;
}
```

🔹这种方式：

- `getInstance()` 写在头文件中没问题；
- 但函数实现 (`doSomething`) 放在 `.cpp`，可避免重复定义。

------



------

## 🧠总结要点

| 写法                                                         | 是否安全 | 原因                           |
| ------------------------------------------------------------ | -------- | ------------------------------ |
| `static Singleton instance;` 定义在 `.cpp`                   | ✅        | 仅定义一次                     |
| `static Singleton& getInstance()` 返回局部静态变量（inline函数） | ✅        | 局部静态 + inline 防止重复定义 |
| `Singleton Singleton::instance;` 定义在头文件                | ❌        | 多重定义                       |
| 将整个 Singleton 类（含实现）放在头文件但非 inline           | ❌        | 链接冲突                       |
