# C++ 面试题：依赖名与两阶段查找

## 1. 模板为什么要分两个阶段检查

模板定义时，编译器还不知道具体模板实参；实例化时才获得完整类型。名称查找因此可概念化为：

```text
第一阶段：模板定义时检查不依赖模板参数的名字和语法
第二阶段：模板实例化时解析依赖模板参数的名字
```

## 2. 为什么需要 typename

```cpp
template <typename Container>
void print_first(const Container& container) {
    typename Container::const_iterator it = container.begin();
}
```

`Container::const_iterator` 依赖模板参数。解析模板定义时，编译器默认不能假设它是类型；`typename` 明确告诉编译器按类型解析。

## 3. 为什么有时需要 template 关键字

```cpp
template <typename Object>
void call(Object& object) {
    object.template convert<int>();
}
```

`object` 的类型依赖模板参数，编译器无法立即确定 `<` 是小于号还是模板实参列表。`template` 消歧义说明 `convert` 是成员模板。

## 4. 依赖基类成员为什么找不到

```cpp
template <typename T>
struct Base {
    void work() {}
};

template <typename T>
struct Derived : Base<T> {
    void run() {
        this->work(); // 让 work 成为依赖名，推迟到实例化阶段查找
    }
};
```

依赖基类可能在某个特化版本中拥有完全不同的成员，因此第一阶段不会无条件在它里面找到 `work`。常见解决方法包括 `this->work()`、`Base<T>::work()` 或 `using Base<T>::work`。

## 5. 一个常见版本陷阱

两阶段查找是模板语言规则，但不同历史版本编译器的严格程度不同。代码不应依赖某个编译器“延迟解析所有内容”的宽松行为，否则换编译器或开启严格模式时可能失败。

## 6. 面试口述版

模板定义和实例化发生在不同上下文，所以名字分为非依赖名和依赖名。非依赖名在定义阶段查找，依赖名通常推迟到实例化。typename 用来说明依赖限定名是类型，template 用来说明依赖对象后的名字是成员模板；访问依赖基类成员时通常要写 this 箭头或显式限定。
