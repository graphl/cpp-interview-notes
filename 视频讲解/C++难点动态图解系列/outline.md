# 视频 01：从 malloc 到 vector——内存与对象生命周期

## Scene 01：封面——“申请内存”其实有三层

- 原始字节存储、对象生命周期、资源所有权不是一回事。
- 用一个问题引入：`new T` 为什么不等于 `malloc(sizeof(T))`？
- 角色：封面/问题引入。
- 视觉想法：三层堆叠模型，由底层字节逐层变成可用对象和 RAII 所有权。

## Scene 02：三层模型

- `malloc/free` 管理原始存储。
- `operator new/delete` 是 C++ 原始存储接口。
- new/delete 表达式增加构造与析构。
- RAII 把释放动作绑定到对象生命周期。
- 角色：概念解释。

## Scene 03：简化 malloc 的块头和空闲链表

- 块头保存大小、空闲状态和前后块。
- payload 位于块头之后，并满足对齐。
- first-fit 沿空闲块寻找空间。
- 角色：数据结构。
- 视觉想法：连续 arena 被切成“块头 + payload”的多个彩色区域。

## Scene 04：分割与合并为什么能减少浪费

- 大空闲块被切成已用块和剩余块。
- free 后先向后、再向前合并相邻空闲块。
- 内部碎片与外部碎片的区别。
- 角色：过程/状态变化。

## Scene 05：new/delete 的四步时间线

- operator new 取得原始存储。
- 构造函数开始对象生命周期。
- 析构函数结束对象生命周期。
- operator delete 归还存储。
- 角色：时间线。

## Scene 06：placement new 和 allocator

- placement new 在已有地址构造对象，不分配存储。
- allocator 分开 `allocate/construct/destroy/deallocate`。
- `capacity` 范围不等于已经存在 T 对象。
- 角色：概念桥接。

## Scene 07：vector 扩容与异常回滚

- 申请新存储、迁移构造、失败回滚、成功后销毁旧元素。
- `move_if_noexcept` 与强异常保证。
- 扩容导致指针、引用和迭代器失效。
- 角色：主流程/总结。

# 视频 02：一次虚函数调用到底发生了什么

## Scene 01：封面——同一个 Base 指针为什么调用不同函数

- 静态类型用于编译检查。
- 动态类型决定最终虚函数实现。
- 角色：封面/悬念。

## Scene 02：普通调用与虚调用对比

- 普通非虚调用的目标通常可直接确定。
- 虚调用需要从对象的动态类型信息间接定位。
- 角色：对比。

## Scene 03：对象、vptr 和 vtable 的常见实现模型

- 对象中常见 vptr 指向类型相关虚表。
- 虚表保存虚函数入口或相关 ABI 信息。
- 强调具体布局属于 ABI，不是标准固定字节结构。
- 角色：内存布局。

## Scene 04：虚调用数据流

- 基类指针指向派生对象中的基类子对象。
- 读取 vptr、索引虚表槽、取得函数地址。
- 把调整后的 `this` 传给最终函数。
- 角色：调用链。

## Scene 05：构造和析构期间为什么“不再多态”

- 对象尚未成为/已经不再是完整最派生对象。
- 各构造析构阶段只调用当前层可用的实现。
- 避免访问尚未构造或已经析构的派生成员。
- 角色：生命周期时间线。

## Scene 06：多继承与 this 指针调整

- 一个完整对象可能包含多个基类子对象。
- 从不同基类指针进入时地址不同。
- 虚调用或转换可能调整 `this`。
- 角色：对象布局/地址变化。

## Scene 07：虚继承如何共享虚基类

- 菱形继承中的重复基类问题。
- 虚继承让最派生对象只保存一个共享虚基类子对象。
- 定位共享基类需要额外间接信息。
- 角色：结构变化。

## Scene 08：RTTI 与 dynamic_cast

- 运行时检查完整对象中的继承关系。
- 指针失败返回空，引用失败抛异常。
- 多继承下转换可能同时完成地址调整。
- 角色：收束/应用。

# 视频 03：条件变量与内存序——线程如何真正看见彼此

## Scene 01：封面——“通知了”为什么线程仍可能出错

- 通知不是状态，条件才是状态。
- 原子不是只有“不可分割”，还涉及可见性与顺序。
- 角色：封面/问题引入。

## Scene 02：先画共享状态和不变量

- 队列、停止标志和容量是共享状态。
- mutex 保护复合不变量。
- 条件变量只负责等待与唤醒。
- 角色：数据结构关系。

## Scene 03：wait 的原子解锁与睡眠

- 持锁检查谓词。
- wait 原子地释放锁并阻塞。
- 被唤醒后重新加锁，再检查谓词。
- 角色：控制流时间线。

## Scene 04：丢失通知与虚假唤醒

- 先修改状态再通知。
- 通知早于等待也不影响谓词正确性。
- 虚假唤醒要求循环检查条件。
- 角色：失败案例对比。

## Scene 05：release/acquire 发布数据

- 生产者先写 payload，再 release store 标志。
- 消费者 acquire load 读到标志后才能安全读取 payload。
- 建立 synchronizes-with 和 happens-before。
- 角色：跨线程数据流。

## Scene 06：relaxed、acquire/release、seq_cst 怎么选

- relaxed 适合独立计数，不发布其他数据。
- acquire/release 表达明确的发布获取关系。
- seq_cst 提供更强且容易推理的默认顺序。
- 角色：比较/决策。

## Scene 07：线程池停止协议

- 停止接收新任务。
- 唤醒所有等待工作线程。
- 决定排空还是取消剩余任务。
- join 后才能销毁共享队列和同步对象。
- 角色：状态机。

## Scene 08：总结——并发正确性的六个问题

- 共享状态、不变量、保护机制、等待条件、退出路径、happens-before。
- 内存序不能替代对象生命周期和资源回收设计。
- 角色：总结清单。

# 视频 04：ELF、PLT/GOT 与第一次动态函数调用

## Scene 01：封面——puts 的真实地址编译时并不知道

- 外部函数地址受共享库、PIE 和 ASLR 影响。
- 重定位和动态加载器负责最终绑定。
- 角色：封面/问题。

## Scene 02：源文件到 ELF

- 预处理、编译、汇编生成目标文件。
- 目标文件保存代码、符号和重定位需求。
- 链接生成可执行文件及动态依赖信息。
- 角色：流程总览。

## Scene 03：section 与 segment

- section 服务链接器，组织代码、数据、符号和重定位。
- segment 服务装载器，描述映射范围和权限。
- 多个 section 可以装入同一个 segment。
- 角色：对比/文件布局。

## Scene 04：execve 到 main

- 内核映射主程序 PT_LOAD 段。
- 进入 ELF interpreter/ld.so。
- 装载依赖库、处理重定位和初始化。
- 启动代码最终调用 main。
- 角色：装载时间线。

## Scene 05：第一次 puts@plt 调用

- caller 进入 PLT 跳板。
- GOT 槽仍指向解析路径。
- ld.so 根据重定位和 link_map 查找符号。
- 解析结果写回 GOT，再跳到 libc puts。
- 角色：核心调用链。

## Scene 06：后续调用与安全选项

- 后续 PLT 读取已修补 GOT，直接跳转。
- `-z now`、partial/full RELRO 改变绑定时机和写权限。
- 具体指令与 section 名依架构和工具链而异。
- 角色：前后对比。

## Scene 07：用命令验证每一步

- `readelf -l/-S/-d/-r` 分别看装载、section、动态标签和重定位。
- `objdump -d/-R` 看 PLT 指令和动态重定位。
- `LD_DEBUG`、`/proc/PID/maps` 看运行时装载与绑定。
- 角色：实验/总结。

# 视频 05：epoll Reactor——一个网络包如何变成业务回调

## Scene 01：封面——epoll 返回的不是业务数据

- epoll 只通知 fd 的就绪状态。
- accept/recv/send 才真正移动数据。
- 角色：封面/纠正常见误解。

## Scene 02：网卡到 socket 接收队列

- 驱动/NAPI 接收数据。
- IP/TCP 完成校验、排序和重组。
- 字节进入 socket 接收队列并触发就绪状态。
- 角色：内核数据流。

## Scene 03：epoll_wait 到连接对象

- 事件循环取得 fd 或稳定连接标识。
- 连接对象持有读缓冲、写缓冲、解析状态和关闭状态。
- fd 可能复用，异步任务不能只记一个旧 fd。
- 角色：数据结构关系。

## Scene 04：ET 模式为什么必须读到 EAGAIN

- fd 必须非阻塞。
- 一次通知后循环 recv，直到接收队列暂时排空。
- 没有读完可能长期等不到新边沿。
- 角色：控制流/失败案例。

## Scene 05：TCP 字节流到完整消息

- TCP 没有应用消息边界。
- 读缓冲可能只有半包，也可能包含多包。
- 协议解码器按长度/分隔符恢复完整帧。
- 角色：协议状态机。

## Scene 06：发送缓冲与背压

- send 只提交当前可接受的数据。
- EAGAIN 后保留剩余数据并关注可写事件。
- 高水位触发暂停读取、限流或断开连接。
- 角色：反馈回路。

## Scene 07：关闭路径与资源生命周期

- 处理 `recv == 0`、错误、超时和业务关闭。
- 撤销 epoll、停止定时器/任务、只关闭一次 fd。
- 对象销毁必须晚于所有异步引用退出。
- 角色：失败路径/生命周期。

## Scene 08：从变慢或崩溃回到证据

- USE 方法先确定 CPU、内存、IO 或网络资源。
- perf/strace/ftrace 下钻到热点或等待。
- core dump/GDB 还原崩溃现场，sanitizer 验证生命周期错误。
- 形成症状、证据、假设、验证、复测闭环。
- 角色：案例总结。
