# 02_简单工厂模式

## 一句话总结

简单工厂模式通过一个工厂函数，根据参数创建不同类型的对象。

## 面试高频问法

1. 什么是简单工厂模式？
2. 简单工厂和工厂方法有什么区别？
3. 简单工厂是否符合开闭原则？
4. 简单工厂适合什么场景？

## 核心原理

客户端不直接 `new` 具体类，而是把创建逻辑集中到工厂函数中。

## C++ 实现

```cpp
class Shape {
public:
    virtual ~Shape() = default;
    virtual void draw() = 0;
};

class Circle : public Shape {
public:
    void draw() override {}
};

class Rect : public Shape {
public:
    void draw() override {}
};

std::unique_ptr<Shape> createShape(const std::string& type) {
    if (type == "circle") return std::make_unique<Circle>();
    if (type == "rect") return std::make_unique<Rect>();
    return nullptr;
}
```

## 优点

- 隐藏对象创建细节。
- 调用方代码更简单。
- 适合产品类型较少的场景。

## 缺点

- 新增产品通常要修改工厂函数。
- 工厂类容易变得臃肿。
- 不完全符合开闭原则。

## 适用场景

- 对象类型有限。
- 创建逻辑简单。
- 希望集中管理创建过程。

## 常见追问

简单工厂不是 GoF 经典 23 种设计模式之一，但面试中经常作为工厂方法的前置问题出现。

## 小红书分享文案

简单工厂适合入门理解“把创建和使用分离”。但它的问题也很明显：每加一个产品，工厂函数可能就要改一次。所以它适合类型少、变化不频繁的场景。
