# 19_状态模式

## 一句话总结

状态模式让对象在内部状态改变时改变行为，看起来像换了一个类。

## 面试高频问法

1. 状态模式解决什么问题？
2. 状态模式和策略模式有什么区别？
3. 状态模式适合什么业务？
4. 状态模式如何消除复杂 if else？

## 核心原理

把不同状态下的行为封装成状态类，由上下文对象持有当前状态。

## C++ 实现

```cpp
class Context;

class State {
public:
    virtual ~State() = default;
    virtual void handle(Context& context) = 0;
};

class Context {
public:
    void setState(std::unique_ptr<State> state) {
        state_ = std::move(state);
    }

    void request() {
        state_->handle(*this);
    }

private:
    std::unique_ptr<State> state_;
};
```

## 优点

- 消除复杂状态分支。
- 状态行为内聚到独立类。
- 状态切换逻辑更清晰。

## 缺点

- 状态类数量增加。
- 状态切换关系复杂时仍需谨慎设计。

## 适用场景

- 订单状态流转。
- 播放器状态。
- TCP 连接状态。
- 工单审批状态。

## 常见追问

策略通常由外部选择；状态通常由对象内部状态自动流转。

## 小红书分享文案

订单从待支付、支付中、已支付、已取消一路流转，如果全写 `if else` 会很乱。状态模式就是把每种状态的行为拆出来，让状态自己管理行为。
