# 03_工厂方法模式

## 一句话总结

工厂方法模式把对象创建延迟到子类，让子类决定创建哪一种具体产品。

## 面试高频问法

1. 工厂方法模式解决什么问题？
2. 工厂方法和简单工厂有什么区别？
3. 工厂方法是否符合开闭原则？
4. 工厂方法有什么缺点？

## 核心原理

定义一个创建对象的抽象接口，由具体工厂类实现创建逻辑。

## C++ 实现

```cpp
class Product {
public:
    virtual ~Product() = default;
    virtual void use() = 0;
};

class ConcreteProduct : public Product {
public:
    void use() override {}
};

class Factory {
public:
    virtual ~Factory() = default;
    virtual std::unique_ptr<Product> create() = 0;
};

class ConcreteFactory : public Factory {
public:
    std::unique_ptr<Product> create() override {
        return std::make_unique<ConcreteProduct>();
    }
};
```

## 优点

- 创建逻辑和使用逻辑解耦。
- 新增产品时可以新增工厂类。
- 更符合开闭原则。

## 缺点

- 类数量增加。
- 对简单场景可能显得复杂。

## 适用场景

- 具体产品类型经常扩展。
- 创建逻辑需要交给子类决定。
- 调用方只依赖抽象产品。

## 常见追问

简单工厂通常是一个工厂类里用条件分支创建对象；工厂方法则是每个具体产品对应一个具体工厂。

## 小红书分享文案

工厂方法的重点不是“工厂”，而是把“创建哪种对象”的变化点交给子类。相比简单工厂，它扩展更友好，但代价是类会变多。
