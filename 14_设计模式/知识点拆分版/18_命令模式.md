# 18_命令模式

## 一句话总结

命令模式把请求封装成对象，使请求可以排队、记录、撤销或重做。

## 面试高频问法

1. 命令模式解决什么问题？
2. 命令模式如何支持撤销和重做？
3. 命令模式适合什么场景？
4. 命令模式和策略模式有什么区别？

## 核心原理

把操作封装成命令对象，调用者只负责触发命令，不关心命令如何执行。

## C++ 实现

```cpp
class Command {
public:
    virtual ~Command() = default;
    virtual void execute() = 0;
    virtual void undo() = 0;
};

class LightOnCommand : public Command {
public:
    void execute() override {}
    void undo() override {}
};
```

## 优点

- 请求发送者和执行者解耦。
- 支持撤销、重做、队列、日志。
- 命令可以作为对象传递和存储。

## 缺点

- 命令类数量可能很多。
- 简单调用场景会显得复杂。

## 适用场景

- 编辑器撤销重做。
- 任务队列。
- 宏命令。
- 事务操作。

## 常见追问

撤销通常需要命令对象保存执行前状态，或者知道如何执行反向操作。

## 小红书分享文案

命令模式的核心是“把操作变成对象”。一旦操作是对象，就能排队、记录、撤销、重做，这也是编辑器和任务系统常用它的原因。
