# 10_外观模式

## 一句话总结

外观模式为复杂子系统提供一个统一、简单的高层接口。

## 面试高频问法

1. 外观模式解决什么问题？
2. 外观模式是否违反开闭原则？
3. 外观模式和适配器模式有什么区别？
4. 外观模式适合什么业务场景？

## 核心原理

用一个 Facade 类封装多个子系统调用，让客户端只和 Facade 交互。

## C++ 实现

```cpp
class CompilerFacade {
public:
    void compile(const std::string& file) {
        preprocess(file);
        parse(file);
        generateCode(file);
    }

private:
    void preprocess(const std::string&) {}
    void parse(const std::string&) {}
    void generateCode(const std::string&) {}
};
```

## 优点

- 简化客户端调用。
- 降低客户端和子系统耦合。
- 隐藏复杂流程。

## 缺点

- 外观类可能变成上帝类。
- 过度封装可能降低灵活性。

## 适用场景

- 编译流程封装。
- 支付流程封装。
- 多模块初始化。
- 第三方 SDK 二次封装。

## 常见追问

外观模式一般不改变已有接口，只是提供更简单入口；适配器是把不兼容接口转换为目标接口。

## 小红书分享文案

外观模式特别适合“调用流程很复杂，但对外只想暴露一个简单入口”的场景。比如 `compile()` 背后有预处理、语法分析、代码生成，但调用方只需要一行。
