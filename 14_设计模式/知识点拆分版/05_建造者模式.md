# 05_建造者模式

## 一句话总结

建造者模式用于一步步构造复杂对象，把构造过程和最终对象表示分离。

## 面试高频问法

1. 建造者模式适合什么场景？
2. 建造者和工厂模式有什么区别？
3. 参数很多的对象为什么适合建造者？
4. C++ 中如何实现链式建造？

## 核心原理

将复杂对象的构建步骤封装到 Builder 中，调用方通过逐步设置参数得到最终对象。

## C++ 实现

```cpp
class HttpRequest {
public:
    std::string url;
    std::string method;
    std::map<std::string, std::string> headers;
};

class HttpRequestBuilder {
public:
    HttpRequestBuilder& setUrl(std::string url) {
        req_.url = std::move(url);
        return *this;
    }

    HttpRequestBuilder& setMethod(std::string method) {
        req_.method = std::move(method);
        return *this;
    }

    HttpRequest build() {
        return req_;
    }

private:
    HttpRequest req_;
};
```

## 优点

- 适合参数多、构造复杂的对象。
- 构造过程清晰。
- 可读性比超长构造函数更好。

## 缺点

- 会增加 Builder 类。
- 简单对象没必要使用。

## 适用场景

- 配置对象。
- HTTP 请求对象。
- SQL 查询构造。
- 游戏角色或复杂业务对象创建。

## 常见追问

工厂模式关注“创建哪种对象”；建造者模式关注“如何一步步创建一个复杂对象”。

## 小红书分享文案

如果一个构造函数参数多到看不懂，建造者模式就该出场了。它能把复杂对象的创建过程拆成清晰步骤，让代码更像在描述意图。
