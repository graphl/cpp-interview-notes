# 17_责任链模式

## 一句话总结

责任链模式让请求沿处理链传递，直到某个处理者处理它。

## 面试高频问法

1. 责任链模式适合什么场景？
2. 责任链模式有什么缺点？
3. 责任链和策略模式有什么区别？
4. HTTP 中间件为什么像责任链？

## 核心原理

每个处理节点持有下一个节点，请求可以被当前节点处理，也可以继续向后传递。

## C++ 实现

```cpp
class Handler {
public:
    virtual ~Handler() = default;

    void setNext(Handler* next) {
        next_ = next;
    }

    virtual void handle(int level) {
        if (next_) {
            next_->handle(level);
        }
    }

private:
    Handler* next_ = nullptr;
};
```

## 优点

- 请求发送者和处理者解耦。
- 可以动态调整处理链。
- 适合多级处理流程。

## 缺点

- 请求可能没人处理。
- 链路过长时调试困难。
- 性能和顺序需要关注。

## 适用场景

- 日志级别处理。
- 审批流程。
- HTTP 中间件。
- 过滤器链。

## 常见追问

策略模式是选择一个算法执行；责任链是让多个处理者按顺序尝试处理请求。

## 小红书分享文案

责任链模式最典型的例子是审批流和中间件。一个请求经过多个节点，每个节点决定自己处理还是继续传递。
