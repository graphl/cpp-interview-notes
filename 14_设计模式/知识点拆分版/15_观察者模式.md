# 15_观察者模式

## 一句话总结

观察者模式在一个对象状态变化时，自动通知所有依赖它的对象。

## 面试高频问法

1. 观察者模式是什么？
2. 观察者和发布订阅有什么区别？
3. C++ 实现观察者要注意什么？
4. 观察者模式适合什么场景？

## 核心原理

主题对象维护观察者列表，状态变化时遍历列表并通知观察者。

## C++ 实现

```cpp
class Observer {
public:
    virtual ~Observer() = default;
    virtual void update(int value) = 0;
};

class Subject {
public:
    void attach(Observer* observer) {
        observers_.push_back(observer);
    }

    void notify(int value) {
        for (auto* observer : observers_) {
            observer->update(value);
        }
    }

private:
    std::vector<Observer*> observers_;
};
```

## 优点

- 支持一对多通知。
- 降低主题和观察者耦合。
- 适合事件驱动场景。

## 缺点

- 通知链复杂时调试困难。
- C++ 中要注意生命周期，避免悬空指针。

## 适用场景

- GUI 事件。
- 消息通知。
- 数据变化刷新视图。
- 事件监听系统。

## 常见追问

观察者通常是主题直接维护观察者列表；发布订阅通常通过事件中心解耦发布者和订阅者。

## 小红书分享文案

观察者模式适合“一处变化，多处响应”。比如数据更新后刷新多个页面、订单状态变化后通知多个系统。C++ 面试要重点讲生命周期管理。
