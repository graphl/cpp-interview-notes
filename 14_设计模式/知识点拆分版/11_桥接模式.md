# 11_桥接模式

## 一句话总结

桥接模式把抽象部分和实现部分分离，使二者可以独立变化。

## 面试高频问法

1. 桥接模式解决什么问题？
2. 桥接和策略模式有什么区别？
3. 桥接适合什么场景？
4. 什么是两个独立变化维度？

## 核心原理

当系统有两个变化维度时，用组合把它们拆开，避免继承层次爆炸。

## C++ 实现

```cpp
class Renderer {
public:
    virtual ~Renderer() = default;
    virtual void renderCircle() = 0;
};

class Shape {
public:
    explicit Shape(Renderer* renderer) : renderer_(renderer) {}
    virtual ~Shape() = default;
    virtual void draw() = 0;

protected:
    Renderer* renderer_;
};

class Circle : public Shape {
public:
    using Shape::Shape;

    void draw() override {
        renderer_->renderCircle();
    }
};
```

## 优点

- 避免多维度继承膨胀。
- 抽象和实现可以独立扩展。
- 更符合组合优于继承。

## 缺点

- 设计理解成本较高。
- 需要提前识别变化维度。

## 适用场景

- 图形类型和渲染引擎。
- 消息类型和发送渠道。
- 平台和业务功能双维变化。

## 常见追问

桥接关注结构解耦；策略关注算法替换。

## 小红书分享文案

桥接模式适合解决“两个维度都在变”的问题。比如图形会变，渲染方式也会变，如果全靠继承，类数量很快爆炸；桥接用组合把两个维度拆开。
