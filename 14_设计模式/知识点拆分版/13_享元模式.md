# 13_享元模式

## 一句话总结

享元模式通过共享大量细粒度对象的公共状态来减少内存开销。

## 面试高频问法

1. 享元模式解决什么问题？
2. 内部状态和外部状态是什么？
3. 享元模式适合什么场景？
4. 享元模式和对象池有什么区别？

## 核心原理

把可共享的内部状态保存在享元对象中，把不可共享的外部状态由调用方传入。

## C++ 实现

```cpp
class Glyph {
public:
    explicit Glyph(char c) : c_(c) {}

    void draw(int x, int y) {
        // x, y 是外部状态
    }

private:
    char c_; // 内部状态
};
```

## 优点

- 减少重复对象。
- 节省内存。
- 适合大量相似对象。

## 缺点

- 需要区分内部状态和外部状态。
- 代码复杂度增加。

## 适用场景

- 字符渲染。
- 棋子对象。
- 地图元素。
- 大量相似 UI 元素。

## 常见追问

内部状态可以共享，比如字符本身；外部状态不能共享，比如字符在屏幕上的坐标。

## 小红书分享文案

享元模式的重点是“共享”。当系统里有大量相似对象时，把公共状态抽出来共享，差异状态由外部传入，就能明显节省内存。
