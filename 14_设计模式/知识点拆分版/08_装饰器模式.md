# 08_装饰器模式

## 一句话总结

装饰器模式在不修改原类的情况下，动态给对象增加功能。

## 面试高频问法

1. 装饰器模式解决什么问题？
2. 装饰器相比继承有什么优势？
3. 装饰器和代理模式有什么区别？
4. C++ 中如何实现装饰器？

## 核心原理

装饰器和被装饰对象实现同一个接口，装饰器内部持有被装饰对象，并在调用前后增强行为。

## C++ 实现

```cpp
class Stream {
public:
    virtual ~Stream() = default;
    virtual void write(const std::string& data) = 0;
};

class FileStream : public Stream {
public:
    void write(const std::string& data) override {}
};

class CompressStream : public Stream {
public:
    explicit CompressStream(std::unique_ptr<Stream> stream)
        : stream_(std::move(stream)) {}

    void write(const std::string& data) override {
        stream_->write(data);
    }

private:
    std::unique_ptr<Stream> stream_;
};
```

## 优点

- 比继承更灵活。
- 功能可以运行期组合。
- 符合开闭原则。

## 缺点

- 装饰层过多时调试困难。
- 对象结构可能变复杂。

## 适用场景

- IO 流增强。
- 加密、压缩、缓存。
- 给已有对象叠加功能。

## 常见追问

装饰器强调功能增强；代理强调访问控制。

## 小红书分享文案

装饰器模式解决的是“功能叠加”。不想为了加缓存、加压缩、加加密写一堆子类，就用装饰器一层层组合。
