# 04_抽象工厂模式

## 一句话总结

抽象工厂模式用于创建一组相关或相互依赖的对象，也就是一个产品族。

## 面试高频问法

1. 抽象工厂解决什么问题？
2. 抽象工厂和工厂方法有什么区别？
3. 什么是产品族？
4. 抽象工厂适合什么业务场景？

## 核心原理

一个工厂负责创建同一产品族中的多个产品对象，调用方只依赖抽象工厂和抽象产品。

## C++ 实现

```cpp
class Button {
public:
    virtual ~Button() = default;
    virtual void paint() = 0;
};

class TextBox {
public:
    virtual ~TextBox() = default;
    virtual void input() = 0;
};

class UIFactory {
public:
    virtual ~UIFactory() = default;
    virtual std::unique_ptr<Button> createButton() = 0;
    virtual std::unique_ptr<TextBox> createTextBox() = 0;
};
```

## 优点

- 保证同一产品族对象一起创建。
- 隔离具体平台或主题差异。
- 调用方不依赖具体类。

## 缺点

- 新增产品等级结构比较麻烦。
- 抽象接口一旦变化，所有具体工厂都要改。

## 适用场景

- 跨平台 UI。
- 多数据库驱动族。
- 多主题控件。
- 一组相关对象需要保持一致。

## 常见追问

工厂方法创建一个产品；抽象工厂创建一组相关产品。

## 小红书分享文案

看到“产品族”就想到抽象工厂。比如 Windows 风格按钮和输入框、Mac 风格按钮和输入框，它们需要成套创建，这就是抽象工厂的典型场景。
