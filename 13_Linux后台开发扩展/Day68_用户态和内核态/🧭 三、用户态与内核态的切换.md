## 🧭 三、用户态与内核态的切换

切换并不是线程/进程切换，而是**同一线程在两种模式间转换**。

### 🔹 典型的切换场景

| 场景         | 切换方向        | 示例                                  |
| ------------ | --------------- | ------------------------------------- |
| 系统调用     | 用户态 → 内核态 | 调用 `read()`, `write()`, `open()` 等 |
| 中断/异常    | 用户态 → 内核态 | 例如键盘中断、页错误（Page Fault）    |
| 系统调用返回 | 内核态 → 用户态 | 内核执行完系统调用后返回用户程序      |
| 中断处理完成 | 内核态 → 用户态 | 中断服务程序结束后恢复原进程          |

------

## 📉 四、切换的代价

切换会带来性能损耗，原因包括：

- 保存/恢复 CPU 上下文；
- 用户态/内核态堆栈切换；
- 切换页表、权限标志；
- 可能触发缓存（TLB、cache）失效。

因此在性能敏感场合（如网络 I/O、系统调用频繁场景），往往会：

- 使用 **零拷贝（zero-copy）**；
- 利用 **mmap、io_uring、eBPF** 等机制减少切换。

## 🧠 五、系统调用是桥梁

系统调用（System Call）是用户态进入内核态的**唯一合法途径**。

流程如下：

```
用户态程序
   ↓ 调用 read()
   ↓
系统调用入口（软中断指令，如 int 0x80 / syscall）
   ↓
内核态：执行 sys_read()
   ↓
完成后返回
   ↓
用户态继续执行
```
