# 🧩  一、基本概念

| 对比项               | 用户态（User Mode）                    | 内核态（Kernel Mode）                     |
| -------------------- | -------------------------------------- | ----------------------------------------- |
| **定义**             | 应用程序运行的模式                     | 操作系统内核运行的模式                    |
| **权限级别**         | 权限受限（通常是 CPU 的 Ring 3）       | 权限最高（CPU 的 Ring 0）                 |
| **可访问资源**       | 只能访问用户空间内存，不能直接访问硬件 | 可访问所有内存、寄存器、IO 端口等硬件资源 |
| **能否执行特权指令** | ❌ 不可以执行（如操作页表、关中断）     | ✅ 可以执行特权指令                        |
| **出错后果**         | 程序崩溃（不会影响系统）               | 系统崩溃（例如内核 panic）                |
| **代表实体**         | 用户程序、应用层代码                   | 内核、驱动程序、系统调用处理函数等        |

## ⚙️ 二、为什么要区分两种模式？

**安全 + 稳定性 + 隔离性**

1. **防止用户程序破坏系统**
   - 用户态不能直接操作硬件或内存管理单元（MMU），防止随意写入内核空间导致系统崩溃。
2. **系统资源受控访问**
   - 通过“系统调用接口（syscall）”来间接访问内核功能。
3. **隔离错误**
   - 用户程序出错时，只会导致自身崩溃，而不会破坏内核或其他进程。
