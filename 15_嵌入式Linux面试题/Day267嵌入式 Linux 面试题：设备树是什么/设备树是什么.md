# 嵌入式 Linux 面试题：设备树是什么

## 1. 面试主要考什么？

设备树 Device Tree 用来描述板级硬件信息，让同一个内核可以适配不同板子。

面试官想听到：

1. DTS、DTSI、DTB 的关系
2. 设备树描述硬件，不写驱动逻辑
3. `compatible` 用于驱动匹配
4. `reg`、`interrupts`、`clocks`、`gpios`
5. 内核如何解析设备树
6. 如何调试设备树问题

---

## 2. 数据流

```text
board.dts
  -> cpp 预处理
  -> dtc 编译
  -> board.dtb
  -> U-Boot 加载 dtb
  -> kernel 解析 dtb
  -> 生成 platform_device
  -> driver probe()
```

---

## 3. 常见节点示例

```dts
uart0: serial@ff000000 {
    compatible = "vendor,chip-uart";
    reg = <0xff000000 0x1000>;
    interrupts = <0 32 4>;
    clocks = <&clk 10>;
    status = "okay";
};
```

关键字段：

1. `compatible`：驱动匹配字符串
2. `reg`：寄存器基地址和长度
3. `interrupts`：中断号和触发方式
4. `clocks`：时钟资源
5. `status`：设备是否启用

---

## 4. 控制流

```text
start_kernel()
  -> setup_arch()
  -> unflatten_device_tree()
  -> of_platform_populate()
  -> 创建 platform_device
  -> platform_driver_register()
  -> compatible 匹配
  -> probe()
```

---

## 5. 驱动里怎么获取设备树资源？

```cpp
struct resource* res;
int irq;

res = platform_get_resource(pdev, IORESOURCE_MEM, 0);
irq = platform_get_irq(pdev, 0);
```

常见接口：

```text
of_property_read_u32()
of_property_read_string()
of_get_named_gpio()
devm_gpiod_get()
platform_get_resource()
platform_get_irq()
devm_ioremap_resource()
```

---

## 6. 调试方法

命令：

```text
ls /sys/firmware/devicetree/base
cat /proc/device-tree/model
find /sys/firmware/devicetree/base -name compatible
dmesg | grep -i probe
dmesg | grep -i of
```

反编译 dtb：

```text
dtc -I dtb -O dts -o out.dts board.dtb
```

---

## 7. 常见坑

1. `compatible` 字符串和驱动表不一致
2. `status = "disabled"` 导致设备不创建
3. `reg` 地址或长度写错
4. `interrupts` 中断号或触发方式写错
5. pinctrl 没配置，外设引脚没有复用出来
6. clock、reset、regulator 没打开

---

## 8. 面试回答

设备树是用来描述硬件资源的，它把板级硬件信息从内核代码里分离出来。DTS 是源码，DTSI 是可复用的公共描述，DTB 是编译后的二进制。U-Boot 把 DTB 传给内核，内核解析后根据节点创建设备，驱动通过 `compatible` 匹配并进入 `probe`。设备树里通常描述寄存器、中断、时钟、GPIO、pinctrl、regulator 等资源。调试时我会看 `/sys/firmware/devicetree/base`、反编译 DTB，并检查 `compatible`、`status` 和 `dmesg` 中的 probe 日志。
