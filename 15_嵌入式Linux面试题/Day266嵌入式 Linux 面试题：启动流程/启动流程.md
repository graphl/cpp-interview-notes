# 嵌入式 Linux 面试题：启动流程

## 1. 面试主要考什么？

嵌入式 Linux 启动流程考的是：从上电到用户空间第一个进程启动，中间每一层负责什么。

面试官想听到：

1. ROM Code
2. Bootloader，例如 U-Boot
3. Kernel 解压和启动
4. 设备树 DTB
5. 根文件系统 rootfs
6. `init` 进程
7. 启动失败如何定位

---

## 2. 控制流

```text
SoC 上电
  -> ROM Code
  -> SPL/TPL
  -> U-Boot
  -> 加载 kernel image
  -> 加载 dtb
  -> 加载 initramfs 或挂载 rootfs
  -> kernel start_kernel()
  -> rest_init()
  -> kernel_init()
  -> 启动 /sbin/init
```

ROM Code 通常在芯片内部，只做最小初始化，并从 eMMC、NAND、NOR、SD 卡或 USB 下载模式加载下一阶段。

---

## 3. 每一层解决什么问题？

1. ROM Code：找到启动介质，加载第一阶段启动程序
2. SPL：初始化 DDR、时钟、电源等基础硬件
3. U-Boot：提供启动命令、环境变量、加载内核和设备树
4. Kernel：初始化内存、调度器、中断、驱动、VFS
5. rootfs：提供用户态程序、动态库、配置文件
6. init：启动系统服务和应用程序

---

## 4. 常见 U-Boot 启动命令

```text
mmc dev 0
fatload mmc 0:1 ${kernel_addr_r} Image
fatload mmc 0:1 ${fdt_addr_r} board.dtb
booti ${kernel_addr_r} - ${fdt_addr_r}
```

如果是 ARM 32 位，可能使用 `bootz` 或 `bootm`。
如果是 ARM64，常见是 `booti`。

---

## 5. Linux 内核启动关键点

常见源码位置：

```text
init/main.c              -> start_kernel()
arch/arm64/kernel/head.S -> 架构相关入口
drivers/of/              -> 设备树解析
init/do_mounts.c         -> rootfs 挂载
```

核心路径：

```text
start_kernel()
  -> setup_arch()
  -> mm_init()
  -> sched_init()
  -> init_IRQ()
  -> driver_init()
  -> rest_init()
  -> kernel_init()
  -> run_init_process()
```

---

## 6. 调试方法

命令：

```text
printenv
bdinfo
mmc list
mmc part
fatls mmc 0:1
bootargs
dmesg
cat /proc/cmdline
```

重点看：

1. kernel 有没有加载到正确地址
2. dtb 地址是否正确
3. `bootargs` 里的 `root=` 是否正确
4. 串口是否输出 `Starting kernel`
5. 是否 panic 在 `VFS: Unable to mount root fs`

---

## 7. 常见坑

1. DDR 没初始化好，内核随机崩溃
2. kernel、dtb、rootfs 地址配置错误
3. 设备树不匹配，驱动 probe 不到
4. `bootargs` 的 `console=` 写错，导致没有串口日志
5. rootfs 缺少 `/sbin/init`
6. rootfs 缺少动态链接器或 libc

---

## 8. 面试回答

嵌入式 Linux 的启动流程可以分成硬件启动、bootloader、kernel、rootfs 和 init 几层。SoC 上电后先执行 ROM Code，加载 SPL 或 U-Boot；U-Boot 初始化基础硬件，加载内核镜像和设备树，并通过 `bootargs` 把启动参数传给内核。内核从架构入口进入 `start_kernel()`，初始化内存、调度、中断、驱动和 VFS，最后挂载根文件系统并启动 `/sbin/init`。如果启动失败，我会先看串口日志、U-Boot 环境变量、`bootargs`、dtb 是否匹配以及 rootfs 是否完整。
