# 嵌入式 Linux 面试题：字符设备驱动怎么写

## 1. 面试主要考什么？

字符设备驱动是 Linux 驱动入门高频题。
它考的是用户态文件操作如何进入内核驱动。

面试官想听到：

1. 设备号
2. `cdev`
3. `file_operations`
4. `/dev/xxx` 设备节点
5. `copy_to_user` 和 `copy_from_user`
6. 阻塞 IO、poll、异步通知等扩展

---

## 2. 数据流

```text
用户程序 read/write/ioctl
  -> glibc
  -> 系统调用
  -> VFS
  -> file_operations
  -> 驱动函数
  -> 硬件寄存器或内核缓冲区
```

---

## 3. 最小驱动骨架

```cpp
static dev_t devno;
static struct cdev demo_cdev;
static struct class* demo_class;

static ssize_t demo_read(struct file* file, char __user* buf,
                         size_t count, loff_t* ppos) {
    char data[] = "hello\n";
    size_t len = min(count, sizeof(data));

    if (copy_to_user(buf, data, len)) {
        return -EFAULT;
    }
    return len;
}

static ssize_t demo_write(struct file* file, const char __user* buf,
                          size_t count, loff_t* ppos) {
    char kbuf[64];
    size_t len = min(count, sizeof(kbuf) - 1);

    if (copy_from_user(kbuf, buf, len)) {
        return -EFAULT;
    }
    kbuf[len] = '\0';
    return len;
}

static const struct file_operations demo_fops = {
    .owner = THIS_MODULE,
    .read = demo_read,
    .write = demo_write,
};
```

注册流程：

```text
alloc_chrdev_region()
  -> cdev_init()
  -> cdev_add()
  -> class_create()
  -> device_create()
```

## 5. 为什么不能直接访问用户态指针？

用户态指针来自用户进程地址空间，内核不能直接信任。

原因：

1. 用户指针可能无效
2. 用户页可能还没映射
3. 直接访问可能导致内核崩溃
4. 需要权限和边界检查

所以要用：

```text
copy_to_user()
copy_from_user()
get_user()
put_user()
```

## 6. 调试方法

命令：

```text
cat /proc/devices

dmesg | tail

echo hello > /dev/demo
cat /dev/demo
```

## 7. 常见坑

1. 忘记 `cdev_add`
2. 设备节点没创建
3. 主设备号和次设备号不匹配
4. `copy_to_user` 返回值理解错
5. 没处理并发访问共享缓冲区
6. 错误路径没有释放设备号、class、device

---

## 8. 面试回答

字符设备驱动的核心是把用户态的文件操作映射到内核里的 `file_operations`。驱动加载时申请设备号，初始化并添加 `cdev`，再通过 `class_create` 和 `device_create` 创建设备节点。用户程序访问 `/dev/xxx` 时会经过系统调用和 VFS，最终调用驱动里的 `open/read/write/ioctl`。驱动和用户空间交换数据时不能直接访问用户指针，要使用 `copy_to_user` 和 `copy_from_user`。调试时可以看 `/proc/devices`、`/dev`、`dmesg` 和 `strace`。
