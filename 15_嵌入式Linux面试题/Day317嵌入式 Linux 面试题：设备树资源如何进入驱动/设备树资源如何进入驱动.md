# 嵌入式 Linux 面试题：设备树资源如何进入驱动

## 1. 这个流程解决什么问题

同一份驱动代码需要适配不同 SoC 和板卡。寄存器地址、中断号、GPIO、时钟和电源不应硬编码在驱动中，而由设备树描述硬件实例，再由内核框架转换成统一资源接口。

## 2. 数据流向

```text
DTS/DTSI 源文件
  -> dtc 编译为 DTB
  -> bootloader 把 DTB 地址传给内核
  -> 内核解析节点和属性
  -> 创建/匹配 platform device
  -> compatible 匹配 platform_driver.of_match_table
  -> 调用 probe
  -> 驱动通过资源 API 取得寄存器、中断、GPIO、clock、regulator
  -> 配置硬件并注册子系统接口
```

## 3. probe 中的典型控制流

```cpp
static int demo_probe(struct platform_device *pdev)
{
    struct device *dev = &pdev->dev;
    struct demo_dev *demo;

    demo = devm_kzalloc(dev, sizeof(*demo), GFP_KERNEL);
    if (!demo)
        return -ENOMEM;

    demo->base = devm_platform_ioremap_resource(pdev, 0);
    if (IS_ERR(demo->base))
        return PTR_ERR(demo->base);

    demo->irq = platform_get_irq(pdev, 0);
    if (demo->irq < 0)
        return demo->irq;

    demo->clk = devm_clk_get_enabled(dev, NULL);
    if (IS_ERR(demo->clk))
        return PTR_ERR(demo->clk);

    platform_set_drvdata(pdev, demo);
    return 0;
}
```

GPIO、pinctrl、regulator 和 reset controller 也应优先通过对应框架获取，而不是直接访问其他模块寄存器。

## 4. 核心关系

```text
device_node（设备树节点）
  -> device.of_node
       -> platform_device.dev
            <compatible 匹配>
       platform_driver
            -> probe(platform_device*)
                 -> 驱动私有数据
                 -> managed resources
```

`devm_*` 资源与 `struct device` 生命周期绑定，probe 后续失败或设备解绑时由 managed resource 框架逆序释放。但硬件状态、正在运行的 DMA、工作队列和跨设备引用仍可能需要驱动显式停止。

## 5. 调试方法

```bash
ls /sys/bus/platform/devices
ls /sys/bus/platform/drivers
cat /proc/iomem
cat /proc/interrupts
find /sys/firmware/devicetree/base -maxdepth 3 -type f
dmesg -w
```

预期确认节点是否存在、compatible 是否匹配、驱动是否绑定、寄存器资源是否冲突、中断计数是否增长。

## 6. 常见错误

1. DTS 节点 `status` 未启用，设备没有创建。
2. `compatible` 字符串与 `of_match_table` 不一致。
3. probe 把 `-EPROBE_DEFER` 当永久错误，破坏依赖资源的延迟探测。
4. 时钟、reset、regulator 的启停顺序与硬件手册不一致。
5. remove/错误路径没有停止中断、DMA、定时器或 workqueue。

## 7. 面试口述版

设备树把板级硬件资源从驱动代码中分离。内核解析 DTB 后根据节点创建设备，compatible 与驱动匹配后调用 probe；驱动再通过 platform、IRQ、GPIO、clock、regulator 等框架取得资源。调试时应沿节点存在、设备创建、驱动匹配、probe 取资源、硬件事件发生这条链逐层验证。
