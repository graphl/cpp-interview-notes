# 嵌入式 Linux 面试题：交叉编译和板级移植流程

## 1. 面试主要考什么？

交叉编译和板级移植考的是：怎么把代码从 PC 构建到目标板运行。

面试官想听到：

1. build、host、target 的区别
2. 交叉编译工具链
3. sysroot
4. U-Boot、Kernel、DTB、rootfs
5. 板级 bring-up 流程
6. 常见运行错误怎么排查

---

## 2. 三个概念

```text
build  : 执行编译动作的机器
host   : 编译出来的程序运行在哪个平台
target : 编译器生成代码面向的平台
```

平时说的交叉编译，通常是：

```text
x86 PC 上编译
  -> 生成 ARM/AArch64 程序
  -> 放到目标板运行
```

---

## 3. 产物链路

```text
Toolchain
  -> U-Boot
  -> Linux Kernel
  -> DTB
  -> rootfs
  -> App
  -> 烧录或网络启动
  -> 目标板运行
```

---

## 4. 常见编译命令

U-Boot：

```text
make CROSS_COMPILE=aarch64-linux-gnu- board_defconfig
make CROSS_COMPILE=aarch64-linux-gnu- -j8
```

Kernel：

```text
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- defconfig
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- Image dtbs modules -j8
```

应用：

```text
aarch64-linux-gnu-gcc main.c -o app
file app
readelf -h app
```

---

## 5. 板级移植基本流程

```text
确认芯片和开发板资料
  -> 移植或配置 U-Boot
  -> 初始化 DDR、时钟、电源
  -> 配置串口日志
  -> 移植 Linux defconfig
  -> 编写或修改设备树
  -> 构建 rootfs
  -> 启动内核
  -> 驱动外设
  -> 跑应用和稳定性测试
```

---

## 6. 调试方法

命令：

```text
file app
readelf -h app
ldd app
uname -m
cat /proc/version
cat /proc/cpuinfo
echo $LD_LIBRARY_PATH
```

典型错误：

```text
Exec format error
No such file or directory
not found
Illegal instruction
```

含义：

1. 架构不匹配
2. 动态链接器不存在
3. libc 版本不匹配
4. CPU 指令集不兼容

---

## 7. 常见坑

1. 工具链架构选错
2. 硬浮点和软浮点 ABI 不匹配
3. sysroot 和目标板 rootfs 不一致
4. 只拷贝应用，没拷贝依赖库
5. 设备树改了但实际启动的还是旧 DTB
6. U-Boot 环境变量没有保存
7. 内核模块版本和内核不匹配

---

## 8. 面试回答

交叉编译就是在一种平台上编译出另一种平台运行的程序。嵌入式 Linux 移植通常包括工具链、U-Boot、Kernel、DTB、rootfs 和应用几个部分。先让 bootloader 能启动并打印串口，再加载内核和设备树，挂载 rootfs，最后验证驱动和应用。排查问题时，我会用 `file` 和 `readelf` 看程序架构，用串口日志看启动阶段，用 `dmesg` 看内核和驱动，用 `ldd` 或检查动态链接器定位用户态运行失败。
