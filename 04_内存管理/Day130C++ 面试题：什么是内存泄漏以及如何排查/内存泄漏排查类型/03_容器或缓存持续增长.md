# 03 容器或缓存持续增长

## 1. 类型定义

有些内存上涨不是传统意义上的“泄漏”，因为对象仍然被程序引用着。

典型情况是容器、全局 map、缓存队列、消息队列一直增长，但没有清理策略或容量上限。

---

## 2. 典型现象

```text
Valgrind 不一定报 definitely lost
内存随请求数量或运行时间增长
业务对象数量持续增加
程序逻辑上仍然持有这些对象
重启后内存恢复
```

---

## 3. 典型代码

裸指针缓存：

```cpp
std::vector<int*> cache;

void add() {
    cache.push_back(new int(10));
}
```

对象缓存无上限：

```cpp
std::unordered_map<std::string, std::string> user_cache;

void cache_user(const std::string& id, const std::string& data) {
    user_cache[id] = data;
}
```

队列只入不出：

```cpp
std::queue<Message> q;

void on_message(const Message& msg) {
    q.push(msg);
}
```

---

## 4. 排查方法

1. 统计容器大小
2. 打印缓存命中率和缓存容量
3. 看内存增长是否和请求量、用户数、消息数相关
4. heaptrack 查看长期存活对象类型
5. 压测后停止请求，看内存是否回落或稳定

示例日志：

```cpp
LOG_INFO("cache size={}", user_cache.size());
```

Linux 查看：

```bash
pmap -x <pid>
cat /proc/<pid>/status
```

---

## 5. 修复方式

给缓存设置上限：

```cpp
constexpr size_t kMaxCacheSize = 10000;

if (cache.size() >= kMaxCacheSize) {
    cache.erase(cache.begin());
}
```

使用 RAII 管理元素：

```cpp
std::vector<std::unique_ptr<int>> cache;
```

设计淘汰策略：

```text
LRU
TTL
容量上限
按业务状态清理
定时清理
```

---

## 6. 面试总结

容器或缓存增长不一定是传统泄漏，但同样会造成内存持续上涨。排查时要看业务对象数量是否持续增加，修复时要明确缓存生命周期、容量上限和淘汰策略。
