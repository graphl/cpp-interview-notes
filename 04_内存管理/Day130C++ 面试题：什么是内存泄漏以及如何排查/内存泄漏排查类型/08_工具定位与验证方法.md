# 08 工具定位与验证方法

## 1. 为什么工具要分场景？

不同内存问题适合不同工具。

```text
Valgrind：精确但慢，适合离线小程序
ASan/LSan：开发测试阶段好用，速度较快
heaptrack：适合看长期分配热点
smaps/pmap：适合判断 heap、mmap、RSS 来源
lsof/strace：适合资源句柄泄漏
```

---

## 2. 基础观察命令

查看进程内存：

```bash
cat /proc/<pid>/status
```

重点字段：

```text
VmRSS
VmSize
VmData
VmStk
VmExe
VmLib
Threads
```

查看内存映射：

```bash
pmap -x <pid>
cat /proc/<pid>/smaps
```

查看 fd：

```bash
ls /proc/<pid>/fd | wc -l
lsof -p <pid>
```

---

## 3. Valgrind

命令：

```bash
valgrind --leak-check=full --show-leak-kinds=all ./app
```

重点关注：

```text
definitely lost
indirectly lost
possibly lost
```

说明：

```text
definitely lost：基本确定泄漏
indirectly lost：被泄漏对象间接引用的内存
possibly lost：可能泄漏，需要结合代码判断
still reachable：程序退出时仍可达，不一定是泄漏
```

---

## 4. AddressSanitizer / LeakSanitizer

编译：

```bash
g++ -fsanitize=address -g main.cpp -o app
```

运行：

```bash
ASAN_OPTIONS=detect_leaks=1 ./app
```

适合发现：

```text
内存泄漏
越界访问
use after free
double free
栈越界
```

---

## 5. heaptrack

命令：

```bash
heaptrack ./app
heaptrack_gui heaptrack.app.gz
```

适合分析：

```text
哪些调用栈分配最多
哪些对象长期存活
内存峰值在哪里
分配热点在哪里
```

---

## 6. strace

跟踪 fd：

```bash
strace -f -e trace=open,close,socket,accept,connect ./app
```

跟踪 mmap：

```bash
strace -f -e trace=mmap,munmap,mremap ./app
```

适合判断：

```text
open 是否没有 close
socket 是否没有关闭
mmap 是否没有 munmap
```

---

## 7. 验证方法

修复后要验证内存是否收敛：

```text
启动服务
执行固定压测流量
观察 RSS / heap / fd / 线程数
停止流量
等待一段时间
看内存是否稳定或回落
重复多轮测试
```

示例观察：

```bash
watch -n 1 "cat /proc/<pid>/status | egrep 'VmRSS|VmData|Threads'"
```

---

## 8. 面试总结

工具不是越多越好，而是要按场景选择。堆泄漏用 Valgrind/ASan/heaptrack，mmap 问题看 smaps/pmap，资源泄漏看 lsof/strace，最终都要通过压测验证内存是否收敛。
