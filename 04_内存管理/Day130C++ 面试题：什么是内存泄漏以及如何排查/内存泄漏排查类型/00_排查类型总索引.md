# C++ 内存泄漏排查类型总索引

## 1. 为什么要按类型排查？

面试中问“如何排查内存泄漏”，不要只回答 Valgrind 或 ASan。

更好的回答方式是先把内存上涨分成不同类型，因为不同类型的现象、工具和修复方式不一样。

```text
进程内存上涨
    |
    +-- 堆内存泄漏
    +-- 智能指针循环引用
    +-- 容器或缓存持续增长
    +-- 异常路径或提前 return 泄漏
    +-- 资源句柄泄漏
    +-- mmap 或第三方库泄漏
    +-- 内存碎片或分配器缓存
    +-- 工具定位与验证
```

## 3. 面试回答主线

```text
第一步：确认现象
    看 RSS、heap、mmap、fd、线程数是否增长

第二步：区分类型
    是真正泄漏，还是缓存、碎片、mmap、资源句柄未释放

第三步：定位来源
    使用 Valgrind / ASan / heaptrack / smaps / lsof 等工具

第四步：回到代码
    检查所有权、生命周期、异常路径、循环引用、缓存策略

第五步：修复验证
    使用 RAII、智能指针、容器、weak_ptr、淘汰策略，再压测验证
```

---

## 4. 一句话总结

C++ 内存泄漏排查不是单纯找 `delete`，而是先把内存上涨类型分清楚，再选择对应工具和修复策略。
