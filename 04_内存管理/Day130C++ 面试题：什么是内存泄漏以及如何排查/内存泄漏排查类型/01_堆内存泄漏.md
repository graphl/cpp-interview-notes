# 01 堆内存泄漏

## 1. 类型定义

堆内存泄漏是最典型的 C++ 内存泄漏。

程序通过 `new`、`new[]`、`malloc`、`calloc`、`realloc` 等方式申请堆内存，但后续没有正确释放，导致这部分内存无法再被程序使用。

---

## 2. 典型现象

```text
VmRSS 持续上涨
heap 区域持续上涨
请求量越大，内存增长越明显
进程长期运行后被 OOM kill
```

查看方式：

```bash
cat /proc/<pid>/status
pmap -x <pid>
cat /proc/<pid>/smaps
```

重点观察：

```text
VmRSS
VmData
[heap]
RssAnon
```

---

## 3. 典型代码

```cpp
void func() {
    int* p = new int(10);
    // 忘记 delete p
}
```

数组场景：

```cpp
void func() {
    char* buf = new char[1024];
    // 忘记 delete[] buf
}
```

`malloc` 场景：

```cpp
void func() {
    void* p = malloc(1024);
    // 忘记 free(p)
}
```

---

## 4. 排查方法

Valgrind：

```bash
valgrind --leak-check=full --show-leak-kinds=all ./app
```

ASan：

```bash
g++ -fsanitize=address -g main.cpp -o app
ASAN_OPTIONS=detect_leaks=1 ./app
```

heaptrack：

```bash
heaptrack ./app
heaptrack_gui heaptrack.app.gz
```

---

## 5. 修复方式

优先使用 RAII：

```cpp
auto p = std::make_unique<int>(10);
```

数组优先使用容器：

```cpp
std::vector<char> buf(1024);
```

需要动态数组时：

```cpp
auto buf = std::make_unique<char[]>(1024);
```

---

## 6. 面试总结

堆内存泄漏通常表现为 heap 和 RSS 持续上涨。排查时可以使用 Valgrind、ASan 或 heaptrack 定位分配栈，修复时优先用 RAII、智能指针和标准容器替代裸 `new/delete`。
