# 02 智能指针循环引用

## 1. 类型定义

智能指针不是绝对安全的。

`std::shared_ptr` 使用引用计数管理对象生命周期。如果两个对象互相持有对方的 `shared_ptr`，引用计数无法归零，对象析构函数不会执行，就会造成逻辑上的内存泄漏。

---

## 2. 典型现象

```text
没有裸 new/delete
Valgrind 可能显示 still reachable
对象析构函数没有打印
业务对象数量持续上涨
进程内存随业务对象累积而上涨
```

---

## 3. 典型代码

```cpp
#include <memory>

struct B;

struct A {
    std::shared_ptr<B> b;
    ~A() {
        // 可能永远不执行
    }
};

struct B {
    std::shared_ptr<A> a;
    ~B() {
        // 可能永远不执行
    }
};

void func() {
    auto a = std::make_shared<A>();
    auto b = std::make_shared<B>();

    a->b = b;
    b->a = a;
}
```

引用关系：

```text
A shared_ptr -> B
B shared_ptr -> A

A 引用计数无法归零
B 引用计数无法归零
```

---

## 4. 排查方法

1. 给关键对象析构函数加日志
2. 检查对象关系图
3. 搜索互相持有的 `shared_ptr`
4. 使用 heaptrack 看长期存活对象
5. 检查 `use_count()`，但不要把它作为业务逻辑依据

搜索：

```bash
grep -R "shared_ptr" .
```

或者：

```bash
rg "shared_ptr"
```

---

## 5. 修复方式

把非所有权关系改为 `weak_ptr`：

```cpp
struct B;

struct A {
    std::shared_ptr<B> b;
};

struct B {
    std::weak_ptr<A> a;
};
```

访问时：

```cpp
if (auto ptr = a.lock()) {
    // 使用 ptr
}
```

---

## 6. 面试总结

`shared_ptr` 只能解决自动释放问题，不能解决所有权设计问题。两个对象互相持有 `shared_ptr` 会造成循环引用，应该用 `weak_ptr` 表达观察关系或反向引用。
