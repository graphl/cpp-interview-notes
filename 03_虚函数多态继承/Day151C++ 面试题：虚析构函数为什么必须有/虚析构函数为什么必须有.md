# Day151 C++ 面试题：虚析构函数为什么必须有

## 1. 面试主要考哪几方面？

虚析构函数这类题，面试一般会围绕下面几个点展开：

1. 析构函数为什么要定义成虚函数
2. 基类指针删除派生类对象会发生什么
3. 不写虚析构函数有什么问题
4. 析构函数调用顺序
5. 哪些类必须写虚析构函数
6. 构造函数能不能是虚函数
7. 虚析构函数和虚函数表的关系

核心一句话：

如果一个类作为基类，并且会通过基类指针删除派生类对象，那么基类析构函数必须声明为虚函数。

---

## 2. 面试题总结

### 2.1 为什么基类析构函数要写成虚函数？

如果使用基类指针指向派生类对象：

```cpp
Base* p = new Derived();
delete p;
```

如果 `Base` 的析构函数不是虚函数，那么 `delete p` 时可能只调用 `Base` 的析构函数，而不会调用 `Derived` 的析构函数。

这样派生类中的资源就无法正确释放。

面试回答：

基类析构函数写成虚函数，是为了通过基类指针删除派生类对象时，能够正确调用派生类析构函数。如果基类析构函数不是虚函数，`delete Base*` 时只会按基类类型析构，派生类析构函数可能不会执行，从而造成资源泄漏或未定义行为。

---

### 2.2 不写虚析构函数会有什么问题？

示例：

```cpp
#include <iostream>
using namespace std;

class Base {
public:
    ~Base() {
        cout << "Base destructor" << endl;
    }
};

class Derived : public Base {
public:
    ~Derived() {
        cout << "Derived destructor" << endl;
    }
};

int main() {
    Base* p = new Derived();
    delete p;
}
```

可能只输出：

```text
Base destructor
```

`Derived` 的析构函数没有被调用。

面试回答：

如果基类析构函数不是虚函数，通过基类指针删除派生类对象时，派生类析构函数不会被正确调用。派生类中如果申请了堆内存、文件句柄、socket、锁等资源，就可能无法释放。

---

### 2.3 正确写法是什么？

正确写法是把基类析构函数声明为 `virtual`：

```cpp
#include <iostream>
using namespace std;

class Base {
public:
    virtual ~Base() {
        cout << "Base destructor" << endl;
    }
};

class Derived : public Base {
public:
    ~Derived() override {
        cout << "Derived destructor" << endl;
    }
};

int main() {
    Base* p = new Derived();
    delete p;
}
```

输出：

```text
Derived destructor
Base destructor
```

面试回答：

基类析构函数加上 `virtual` 后，`delete Base*` 会发生动态绑定，先调用派生类析构函数，再调用基类析构函数，从而保证整个对象被完整析构。

---

### 2.4 析构函数的调用顺序是什么？

析构顺序和构造顺序相反。

构造时：

```text
先构造基类，再构造派生类
```

析构时：

```text
先析构派生类，再析构基类
```

例如：

```text
Derived::~Derived()
Base::~Base()
```

面试回答：

对象析构时，先调用最派生类的析构函数，再依次调用基类析构函数。这样可以保证派生类先释放自己管理的资源，然后基类再释放基类部分的资源。

---

### 2.5 哪些类必须写虚析构函数？

需要写虚析构函数的情况：

1. 类作为基类使用
2. 类中有虚函数
3. 可能通过基类指针删除派生类对象
4. 类用于多态场景

不一定需要写虚析构函数的情况：

1. 类不作为基类
2. 不会发生多态删除
3. 类是值语义类型
4. 类明确禁止继承

面试回答：

只要一个类要作为多态基类使用，就应该提供虚析构函数。尤其是类中已经有虚函数时，通常析构函数也应该是虚函数。否则通过基类指针释放派生类对象时可能出问题。

---

### 2.6 析构函数是虚函数会有什么代价？

有虚析构函数意味着类中通常会有虚函数表指针。

可能带来的影响：

1. 对象大小可能增加一个虚表指针
2. 析构调用需要动态绑定
3. 有轻微运行时开销

但是在多态基类中，这个开销通常是值得的。

面试回答：

虚析构函数会带来虚函数机制的开销，比如对象中可能多一个虚表指针，调用析构函数时需要动态绑定。但如果这个类本来就是多态基类，通常已经有虚函数表，这个开销可以接受，而且能保证析构正确性。

---

### 2.7 构造函数可以是虚函数吗？

构造函数不能是虚函数。

原因是对象在构造期间，派生类部分还没有构造完成，虚函数机制依赖的动态类型还不完整。

但是析构函数可以是虚函数。

面试回答：

构造函数不能是虚函数，因为构造函数执行时对象还没有完整构造出来，还不能根据完整的动态类型进行虚调用。析构函数可以是虚函数，因为删除对象时需要根据动态类型决定先调用哪个析构函数。

---

## 3. 高频追问

### 3.1 如果基类没有虚函数，还需要虚析构函数吗？

如果这个类不会被当作基类使用，或者不会通过基类指针删除派生类对象，就不一定需要。

但如果它要作为多态基类使用，就应该写虚析构函数。

---

### 3.2 有虚函数就一定要有虚析构函数吗？

一般建议有。

因为类中有虚函数，通常说明这个类会被用于多态。如果它可能被继承，并且可能通过基类指针释放对象，析构函数就应该是虚函数。

---

### 3.3 派生类析构函数需要写 `virtual` 吗？

不必须。

只要基类析构函数是虚函数，派生类析构函数自动也是虚函数。

但可以写 `override`，让编译器帮忙检查：

```cpp
~Derived() override = default;
```

---

### 3.4 虚析构函数可以是纯虚函数吗？

可以。

但纯虚析构函数必须有函数体。

```cpp
class Base {
public:
    virtual ~Base() = 0;
};

Base::~Base() {}
```

原因是派生类析构后，仍然会调用基类析构函数，所以基类析构函数必须有定义。

---

### 3.5 `delete` 基类指针时发生了什么？

如果基类析构函数是虚函数：

```text
先根据动态类型调用 Derived 析构函数
再调用 Base 析构函数
最后释放内存
```

如果不是虚函数：

```text
可能只调用 Base 析构函数
派生类资源无法释放
```

---

## 4. 最终背诵版

如果一个类作为基类使用，并且可能通过基类指针删除派生类对象，那么基类析构函数必须声明为虚函数。

原因是 `Base* p = new Derived(); delete p;` 这种场景下，如果 `Base` 的析构函数不是虚函数，就可能只调用 `Base` 的析构函数，而不会调用 `Derived` 的析构函数，导致派生类资源无法释放。

把基类析构函数声明为 `virtual` 后，删除基类指针时会发生动态绑定，先调用派生类析构函数，再调用基类析构函数，保证对象完整析构。

一般来说，只要一个类是多态基类，尤其是类中已经有虚函数，就应该提供虚析构函数。构造函数不能是虚函数，但析构函数可以是虚函数。
