## 问题背景

在 C++ 中，**基类指针指向派生类对象** 是常见用法：

```
Base* p = new Derived();
```

如果 `Base` 的析构函数不是虚函数，那么当 `delete p;` 时，只会调用 `Base` 的析构函数，而不会调用 `Derived` 的析构函数，造成 **派生类资源没有被释放**，从而 **内存泄漏** 或 **资源泄露**。

##  为什么要设为虚函数

### ✅ 作用

- **保证析构函数多态性**
   当通过基类指针/引用销毁对象时，能够正确调用派生类的析构函数。
- **避免资源泄露**
   特别是派生类里分配了堆资源、开了文件、网络连接等情况。
- **符合面向对象的设计**
   “多态创建，多态销毁”。如果基类有虚函数（打算多态使用），析构函数通常也应该是虚的。

## **并不是所有类的析构函数都要虚**

- 只有当类会被当作 **基类**，并且 **可能通过基类指针删除对象** 时，才需要虚析构。
- 如果类不打算被继承，析构函数可以不用虚，甚至加上 `final` 修饰类。

**虚析构函数会增加一点开销**

- 类需要虚表指针（vptr），对象体积会稍微增加。
- 但这是为安全付出的必要代价。

**纯虚析构函数是合法的**

- 可以将析构函数声明为 `virtual ~Base() = 0;`，让类变成抽象类，但必须提供定义：

  ```
  virtual ~Base() = 0;
  Base::~Base() {}
  ```
