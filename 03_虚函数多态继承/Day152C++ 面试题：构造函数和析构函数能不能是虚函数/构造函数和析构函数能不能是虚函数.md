# Day152 C++ 面试题：构造函数和析构函数能不能是虚函数

## 1. 面试主要考哪几方面？

这道题面试中经常和虚函数、对象构造过程、析构顺序一起问。

主要考：

1. 构造函数能不能是虚函数
2. 析构函数能不能是虚函数
3. 为什么构造函数不能是虚函数
4. 为什么析构函数可以是虚函数
5. 构造和析构期间调用虚函数会发生什么
6. 虚函数表指针什么时候建立
7. 多态删除对象为什么依赖虚析构函数

核心一句话：

构造函数不能是虚函数，析构函数可以是虚函数，而且多态基类通常必须把析构函数声明为虚函数。

---

## 2. 面试题总结

### 2.1 构造函数能不能是虚函数？

不能。

C++ 不允许构造函数声明为虚函数。

错误写法：

```cpp
class Base {
public:
    virtual Base() {}
};
```

这段代码无法通过编译。

面试回答：

构造函数不能是虚函数。因为虚函数依赖对象的动态类型和虚函数表，而构造函数执行时对象还没有完整构造出来，派生类部分还不存在，无法根据完整动态类型进行虚调用。

---

### 2.2 为什么构造函数不能是虚函数？

虚函数调用依赖两个东西：

1. 对象已经存在
2. 对象中的虚函数表指针已经指向正确的虚函数表

但是构造函数执行时，对象正在构造，还不是一个完整对象。

构造过程大致是：

```text
分配内存
构造基类部分
构造成员对象
构造派生类部分
```

当基类构造函数执行时，派生类部分还没有构造完成。

如果此时允许构造函数是虚函数，就会出现一个问题：

```text
对象还没构造完成，却要按最终派生类类型调用函数
```

这是不安全的。

面试回答：

构造函数不能是虚函数，本质原因是构造函数执行时对象的动态类型还没有完整形成。虚函数机制是为了根据对象的动态类型进行调用，但构造过程中派生类部分还没初始化完成，所以不能把构造函数设计成虚函数。

---

### 2.3 析构函数能不能是虚函数？

可以。

而且在多态基类中，析构函数通常必须是虚函数。

正确写法：

```cpp
class Base {
public:
    virtual ~Base() {}
};
```

面试回答：

析构函数可以是虚函数。它的作用是保证通过基类指针删除派生类对象时，可以先调用派生类析构函数，再调用基类析构函数，从而完整释放对象资源。

---

### 2.4 为什么析构函数需要是虚函数？

看下面代码：

```cpp
#include <iostream>
using namespace std;

class Base {
public:
    ~Base() {
        cout << "Base destructor" << endl;
    }
};

class Derived : public Base {
public:
    ~Derived() {
        cout << "Derived destructor" << endl;
    }
};

int main() {
    Base* p = new Derived();
    delete p;
}
```

如果 `Base` 的析构函数不是虚函数，`delete p` 时可能只调用：

```text
Base destructor
```

派生类析构函数没有执行，派生类资源可能泄漏。

改成虚析构函数：

```cpp
class Base {
public:
    virtual ~Base() {
        cout << "Base destructor" << endl;
    }
};
```

此时输出：

```text
Derived destructor
Base destructor
```

面试回答：

析构函数声明为虚函数后，`delete Base*` 会发生动态绑定，根据对象真实类型先调用派生类析构函数，然后再调用基类析构函数。如果基类析构函数不是虚函数，通过基类指针删除派生类对象会导致未定义行为。

---

### 2.5 构造函数中调用虚函数会发生什么？

构造函数中可以调用虚函数，但不会触发派生类的多态行为。

示例：

```cpp
#include <iostream>
using namespace std;

class Base {
public:
    Base() {
        func();
    }

    virtual void func() {
        cout << "Base::func" << endl;
    }
};

class Derived : public Base {
public:
    void func() override {
        cout << "Derived::func" << endl;
    }
};

int main() {
    Derived d;
}
```

输出：

```text
Base::func
```

不是：

```text
Derived::func
```

面试回答：

构造函数中调用虚函数，不会调用派生类版本。因为基类构造函数执行时，派生类部分还没有构造完成，此时对象会被当作当前正在构造的基类对象来看待。

---

### 2.6 析构函数中调用虚函数会发生什么？

析构函数中调用虚函数，也不会表现出完整的多态行为。

析构过程是：

```text
先析构派生类
再析构基类
```

当基类析构函数执行时，派生类部分已经析构完成。

所以基类析构函数中调用虚函数，也只会调用基类自己的版本。

面试回答：

析构函数中调用虚函数时，不会再调用派生类版本。因为执行基类析构函数时，派生类部分已经被销毁，对象已经不再是完整的派生类对象。

---

### 2.7 构造和析构期间为什么不建议调用虚函数？

原因是：

1. 构造期间派生类部分还没初始化
2. 析构期间派生类部分已经销毁
3. 此时虚调用不会表现出预期的多态
4. 容易造成逻辑错误

面试回答：

构造函数和析构函数中都不建议调用虚函数。虽然语法上可以调用普通虚函数，但不会触发期望中的派生类多态行为，容易让代码看起来像多态，实际却不是多态。

---

### 2.8 构造函数和析构函数的区别总结

| 问题 | 构造函数 | 析构函数 |
|---|---|---|
| 能否是虚函数 | 不能 | 可以 |
| 是否建议虚 | 不允许 | 多态基类建议必须虚 |
| 执行阶段 | 对象正在构造 | 对象正在销毁 |
| 动态类型是否完整 | 不完整 | 正在逐步退化 |
| 典型作用 | 初始化对象 | 释放资源 |

面试回答：

构造函数不能是虚函数，因为对象还没有构造完成；析构函数可以是虚函数，并且多态基类必须使用虚析构函数，保证通过基类指针删除派生类对象时能正确释放资源。

## 3. 高频追问

### 3.1 构造函数为什么没有 virtual 机制？

因为构造函数的任务是创建对象，而虚函数机制依赖对象已经创建完成。

构造函数执行时对象还没完整存在，所以无法根据完整动态类型进行虚调用。

---

### 3.2 析构函数为什么可以 virtual？

因为删除对象时，对象已经存在，需要根据对象真实类型决定析构顺序。

虚析构函数可以保证：

```text
Derived::~Derived()
Base::~Base()
```

按正确顺序执行。

---

### 3.3 析构函数不写 virtual 一定会出问题吗？

不一定。

如果类不会被继承，或者不会通过基类指针删除派生类对象，就不一定需要虚析构函数。

但是如果类是多态基类，就应该写虚析构函数。

---

### 3.4 构造函数中调用虚函数是编译错误吗？

不是。

构造函数中可以调用虚函数，但调用的是当前类版本，不会调用派生类 override 的版本。

---

### 3.5 析构函数中调用虚函数是编译错误吗？

不是。

析构函数中也可以调用虚函数，但同样不会调用已经析构掉的派生类版本。

---

## 4. 最终背诵版

构造函数不能是虚函数，析构函数可以是虚函数。

构造函数不能是虚函数，是因为构造函数执行时对象还没有完整构造出来，派生类部分还不存在，而虚函数机制依赖对象的动态类型和虚函数表，所以构造函数不能 virtual。

析构函数可以是虚函数，而且多态基类通常必须写虚析构函数。这样通过基类指针删除派生类对象时，才能先调用派生类析构函数，再调用基类析构函数，保证对象完整释放。

另外，构造函数和析构函数中都不建议调用虚函数。构造期间派生类还没构造完成，析构期间派生类已经被销毁，所以此时虚调用不会表现出正常多态。
