# C++ 面试题：容器如何选择

## 1. 核心原则

选择 STL 容器时，先看操作模式：

1. 是否需要随机访问
2. 是否频繁中间插入删除
3. 是否需要有序
4. 是否只需要快速查找
5. 是否需要唯一性
6. 是否需要头尾操作

---

## 2. 常见选择

| 需求 | 推荐容器 |
|---|---|
| 默认选择、随机访问、尾插 | `vector` |
| 频繁头尾插入删除 | `deque` |
| 频繁中间插入删除，已有位置 | `list` |
| 固定大小数组 | `array` |
| key-value 有序映射 | `map` |
| key-value 快速查找 | `unordered_map` |
| 有序去重集合 | `set` |
| 快速去重集合 | `unordered_set` |
| 后进先出 | `stack` |
| 先进先出 | `queue` |
| 按优先级取最大或最小 | `priority_queue` |

---

## 3. 为什么默认推荐 vector？

原因：

1. 内存连续
2. 缓存友好
3. 随机访问快
4. 尾部插入效率高
5. 实际性能通常很好

即使 `list` 中间插入是 O(1)，如果找位置需要 O(n)，整体仍然不一定比 `vector` 快。

---

## 4. 典型误区

| 误区 | 正确认识 |
|---|---|
| 中间插入就用 list | 如果需要先查找位置，仍然可能 O(n) |
| unordered_map 永远比 map 快 | 哈希质量、内存、顺序需求都会影响 |
| reserve 后可以用下标访问 | `reserve` 不改变 size |
| deque 是完全连续内存 | deque 是分段连续 |

---

## 5. 面试回答

容器选择要根据访问模式决定。默认优先考虑 `vector`，因为它连续内存、缓存友好、随机访问快。需要头尾高效插删用 `deque`，需要中间节点级插删用 `list`，需要有序映射用 `map`，只追求平均快速查找用 `unordered_map`。
