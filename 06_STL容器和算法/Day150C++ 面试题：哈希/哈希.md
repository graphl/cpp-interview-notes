# Day150 C++ 面试题：哈希

## 1. 面试主要考哪几方面？

哈希这类题，面试一般不会只问“哈希是什么”，而是会围绕下面几个点展开：

1. 哈希表的基本原理
2. 哈希函数的作用
3. 哈希冲突怎么解决
4. `unordered_map` 的底层实现
5. `unordered_map` 和 `map` 的区别
6. 负载因子和 rehash
7. 自定义类型如何作为 key
8. 哈希表的时间复杂度和适用场景

核心一句话：

哈希表通过哈希函数把 key 映射到桶中，理想情况下可以实现 O(1) 的查找、插入和删除。

---

## 2. 面试题总结

### 2.1 什么是哈希？

哈希是一种通过哈希函数把 key 映射成一个整数，再根据这个整数找到存储位置的技术。

在哈希表中，通常会有一个桶数组：

```cpp
index = hash(key) % bucket_count;
```

通过这个下标，就可以快速定位 key 对应的位置。

面试回答：

哈希的核心思想是用空间换时间。通过哈希函数把 key 映射到数组下标，从而避免线性遍历。理想情况下，查找、插入、删除的时间复杂度都是 O(1)。

---

### 2.2 哈希函数有什么要求？

哈希函数的作用是把 key 转换成 hash 值。

一个好的哈希函数应该满足：

1. 相同 key 的 hash 值必须相同
2. 不同 key 的 hash 值尽量不同
3. 分布尽量均匀
4. 计算速度要快

必须满足：

```text
a == b  =>  hash(a) == hash(b)
```

但是不要求：

```text
hash(a) == hash(b)  =>  a == b
```

因为不同 key 可能产生相同 hash 值，这就是哈希冲突。

面试回答：

哈希函数最重要的是保证相等的 key 一定得到相同的 hash 值，同时尽量让不同 key 均匀分布到不同桶中，减少冲突。如果哈希函数分布不好，大量元素会落到同一个桶，哈希表性能会退化。

---

### 2.3 什么是哈希冲突？

哈希冲突是指不同的 key 被映射到了同一个桶。

例如：

```text
hash(key1) % 10 == 3
hash(key2) % 10 == 3
```

即使 `key1` 和 `key2` 不相等，它们也可能落到同一个桶中。

面试回答：

哈希冲突无法完全避免，因为 key 的取值空间通常远大于桶数组大小。只要不同 key 映射到同一个桶，就发生了哈希冲突。

---

### 2.4 哈希冲突怎么解决？

常见方式有两种：

1. 拉链法
2. 开放寻址法

拉链法：

每个桶后面挂一个链表或其他结构，冲突的元素都放到同一个桶后面。

```text
bucket[0] -> nullptr
bucket[1] -> node1 -> node2
bucket[2] -> node3
```

开放寻址法：

所有元素都放在数组中，如果当前位置被占用，就继续寻找下一个可用位置。

常见探测方式：

1. 线性探测
2. 二次探测
3. 双重哈希

面试回答：

哈希冲突常见解决方式是拉链法和开放寻址法。拉链法是在桶后面挂链表，冲突元素都放在同一个桶的链表中；开放寻址法是在数组中继续探测下一个空位置。C++ 的 `unordered_map` 通常可以按桶数组加链表的方式理解。

---

### 2.5 `unordered_map` 底层是什么？

`unordered_map` 底层是哈希表。

它大致包含：

1. 桶数组
2. 哈希函数
3. 相等比较函数
4. 冲突处理机制

查找流程：

1. 对 key 计算 hash 值
2. 根据 hash 值找到桶
3. 在桶中比较 key 是否相等
4. 找到则返回，找不到则说明不存在

面试回答：

`unordered_map` 底层是哈希表。它先通过 hash 函数计算 key 的 hash 值，再映射到某个桶中。如果发生冲突，就在桶内继续查找。平均情况下查找是 O(1)，但如果冲突严重，所有元素都落到同一个桶中，最坏会退化成 O(n)。

---

### 2.6 `unordered_map` 和 `map` 有什么区别？

| 对比项 | `map` | `unordered_map` |
|---|---|---|
| 底层结构 | 红黑树 | 哈希表 |
| 元素顺序 | 按 key 有序 | 无序 |
| 查找复杂度 | O(log n) | 平均 O(1)，最坏 O(n) |
| 是否支持范围查询 | 支持 | 不适合 |
| 适用场景 | 需要有序 | 只需要快速查找 |

面试回答：

`map` 底层是红黑树，元素按 key 有序，查找、插入、删除是 O(log n)。`unordered_map` 底层是哈希表，元素无序，平均查找、插入、删除是 O(1)，但最坏情况下可能退化到 O(n)。如果需要有序遍历或范围查询，用 `map`；如果只关心快速查找，一般用 `unordered_map`。

---

### 2.7 什么是负载因子？

负载因子表示哈希表的拥挤程度。

```text
load_factor = 元素个数 / 桶数量
```

C++ 中可以这样查看：

```cpp
std::unordered_map<int, int> mp;

mp.load_factor();      // 当前负载因子
mp.max_load_factor();  // 最大负载因子
```

面试回答：

负载因子表示哈希表中元素数量和桶数量的比例。负载因子越高，说明桶越拥挤，哈希冲突越可能增加。当负载因子超过阈值时，哈希表通常会扩容并触发 rehash。

---

### 2.8 什么是 rehash？

rehash 是指重新调整桶的数量，并把已有元素重新分配到新的桶中。

因为桶数量变了，所以元素所在位置也可能变化：

```cpp
index = hash(key) % bucket_count;
```

C++ 中常见相关接口：

```cpp
mp.rehash(100);   // 调整桶数量至少为 100
mp.reserve(100);  // 预留能容纳 100 个元素的空间
```

面试回答：

rehash 是哈希表扩容后重新计算元素桶位置的过程。它会重新分配桶，并让已有元素重新落位，所以开销比较大，也可能导致迭代器失效。如果提前知道数据量，可以使用 `reserve` 减少 rehash 次数。

---

### 2.9 `unordered_map` 的迭代器什么时候失效？

常见情况：

1. rehash 后，迭代器会失效
2. erase 某个元素后，指向该元素的迭代器失效
3. insert 如果触发 rehash，也会导致迭代器失效

删除时推荐写法：

```cpp
for (auto it = mp.begin(); it != mp.end(); ) {
    if (it->second == 0) {
        it = mp.erase(it);
    } else {
        ++it;
    }
}
```

面试回答：

`unordered_map` 的迭代器主要在 rehash 时失效，因为 rehash 会重新分配桶并移动元素位置。删除元素时，被删除元素对应的迭代器失效，所以遍历删除时要使用 `erase` 的返回值继续遍历。

---

### 2.10 自定义类型如何作为 `unordered_map` 的 key？

自定义类型作为 key，需要提供：

1. 哈希函数
2. 相等比较函数

示例：

```cpp
#include <unordered_map>

struct Point {
    int x;
    int y;

    bool operator==(const Point& other) const {
        return x == other.x && y == other.y;
    }
};

struct PointHash {
    size_t operator()(const Point& p) const {
        return std::hash<int>()(p.x) ^
               (std::hash<int>()(p.y) << 1);
    }
};

int main() {
    std::unordered_map<Point, int, PointHash> mp;
    mp[{1, 2}] = 100;
}
```

面试回答：

自定义类型作为 `unordered_map` 的 key 时，需要提供 hash 函数和相等比较。hash 函数用于决定元素落在哪个桶，相等比较用于发生冲突时判断两个 key 是否真的相等。必须保证如果两个 key 相等，那么它们的 hash 值也相等。

---

### 2.11 哈希表的时间复杂度是多少？

平均情况：

```text
查找 O(1)
插入 O(1)
删除 O(1)
```

最坏情况：

```text
查找 O(n)
插入 O(n)
删除 O(n)
```

面试回答：

哈希表平均时间复杂度是 O(1)，但这是建立在哈希函数分布均匀、冲突较少的前提下。如果哈希函数不好，或者大量 key 被构造到同一个桶中，哈希表可能退化成链表查找，最坏时间复杂度就是 O(n)。

---

### 2.12 哈希表适合什么场景？

适合：

1. 快速查找
2. 去重
3. 计数
4. 缓存
5. key 到 value 的映射

不适合：

1. 需要有序遍历
2. 需要范围查询
3. 对最坏时间复杂度要求特别严格
4. 哈希函数难以设计的复杂 key

面试回答：

哈希表适合快速查找、去重、计数、缓存等场景。如果需要有序性或者范围查询，哈希表就不合适，应该考虑红黑树结构，比如 `map` 或 `set`。

## 3. 高频追问

### 3.1 为什么哈希表平均是 O(1)，最坏是 O(n)？

因为理想情况下 key 会均匀分布到不同桶中，可以直接定位。

但如果大量 key 落到同一个桶中，就需要在桶内继续查找，可能退化成链表遍历，所以最坏是 O(n)。

---

### 3.2 `reserve` 和 `rehash` 有什么区别？

`rehash(n)` 是要求桶数量至少为 n。

`reserve(n)` 是要求哈希表预留能容纳 n 个元素的空间，内部会结合最大负载因子计算需要多少桶。

面试中一般记：

```text
rehash 管桶数量
reserve 管元素容量
```

---

### 3.3 为什么自定义 key 既要 hash，又要 `==`？

hash 用来定位桶。

`==` 用来判断 key 是否真正相等。

因为不同 key 可能有相同 hash 值，所以不能只靠 hash 判断两个 key 是否相等。

---

### 3.4 哈希表和红黑树怎么选？

如果只需要快速查找，用哈希表。

如果需要有序遍历、范围查询、稳定的 O(log n) 复杂度，用红黑树。

对应到 C++：

```text
快速查找：unordered_map
有序遍历：map
```

---

## 4. 最终背诵版

哈希表是一种通过哈希函数把 key 映射到桶中的数据结构。它的核心思想是用空间换时间，理想情况下查找、插入、删除都是 O(1)。

哈希表最重要的问题是哈希函数和哈希冲突。哈希函数要保证相等的 key 有相同的 hash 值，并且尽量让 key 均匀分布。哈希冲突常见解决方式有拉链法和开放寻址法。

C++ 中的 `unordered_map` 底层就是哈希表，平均查找复杂度是 O(1)，但如果冲突严重，最坏可能退化到 O(n)。它和 `map` 的区别是：`map` 底层是红黑树，元素有序，复杂度是 O(log n)；`unordered_map` 元素无序，但平均查找更快。

哈希表还有负载因子和 rehash 的概念。负载因子过高时，冲突会增加，哈希表可能扩容并重新计算元素位置，这个过程叫 rehash。rehash 开销较大，也可能导致迭代器失效。
