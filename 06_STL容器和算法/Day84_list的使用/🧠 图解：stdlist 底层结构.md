## 🧠 图解：std::list 底层结构

```
 ┌───────────────┐      ┌───────────────┐      ┌───────────────┐
 │   value = 10  │      │   value = 20  │      │   value = 30  │
 │ prev ────────┼────►  │ prev ────────┼────►  │ prev ────────┼──┐
 │ next ◄───────┼◄────  │ next ◄───────┼◄────  │ next ◄───────┼──┘
 └───────────────┘      └───────────────┘      └───────────────┘
```

每个节点包含：

- 元素 `value`
- 指向前驱 `prev`
- 指向后继 `next`

------

## ⚔ 关键理解：为什么插入/删除是 O(1)？

因为只需要改指针👇

### 插入位置已知

```
 A → new → B
```

只更新 **4 个指针** → O(1)

### 删除已知节点

```
 A → (del) → B
```

只断开并释放该节点 → O(1)

🚨 查找位置仍是 O(n)，所以**已知迭代器插入快，不是随便插入都快！**

------

## 📍 迭代器稳定性图解

相比 vector：

```
vector 插入：会整体挪动元素 → 所有旧迭代器失效
list 插入：只改指针 → 其他迭代器不变
```

👉 **只有指向被删节点的迭代器失效，其他迭代器永远安全**

------

## 💡 对比记忆：为什么 list 遍历慢？

```
vector：顺序连续内存 → 一次 cache 预取很多元素
list：节点离散内存 → cache 命中率差
```

一句话总结👇

> list 优化插入删除，vector 优化遍历访问。

## 🏆 list 独家技能：splice（O(1））

```
list A:  [10] — [20] — [30]
list B:  [100] — [200]

B.splice(pos, A, node20)
```

👇结果

```
list A: [10] — [30]
list B: [100] — [20] — [200]
```

✨ **无拷贝、无移动、无构造 → 仅改指针**
