# C++ 手写实现题补充题单与优先级

这份清单用于回答两个问题：

1. 当前 46 个 Day 目录之外，还有哪些值得单独练习的手写题？
2. 哪些题应该优先补，哪些只适合作为特定方向的进阶题？

筛选标准不是“能不能出题”，而是：

- 能否独立考察一种重要的数据结构、资源模型或并发约束；
- 是否具有清晰的最小可实现版本；
- 是否能产生有价值的边界、复杂度、异常安全或线程安全追问；
- 是否与已有题目形成自然的学习链，而不是简单换皮。

## 1. 当前覆盖结论

当前专题原有 46 个 Day 目录，第一批扩展完成后共有 54 个 Day 目录，已经覆盖：

- 字符串和原始内存函数；
- `string`、`vector`、智能指针及常用容器；
- 链表、排序、二分、TopK 和 LRU；
- 内存池、对象池、allocator、`malloc/free`；
- 阻塞队列、线程池、读写锁和 SPSC 无锁队列；
- 定时器、跳表、Reactor 和部分类型擦除组件。

不过，Day101 和 Day109 都是 `string` 实现，因此独立题目数量比目录数少一个。第一批扩展已经补入二叉树遍历、二叉搜索树、Trie、LFU、简化版 `variant`、并查集、图的 BFS/DFS 和 Bitmap。当前后续缺口主要是：

1. 后台开发常见的限流、连接池、一致性哈希和布隆过滤器尚未进入手写专题；
2. 并发部分从阻塞队列直接跳到 SPSC，缺少自旋锁、信号量和更复杂无锁结构的过渡；
3. 现有 `weak_ptr` 和红黑树题目的标题范围大于实际实现范围。

## 2. 先补现有题目的实现缺口

新增题目之前，下面几项优先级更高。

### 2.1 Day111：补全真正的 weak_ptr

当前代码只实现了简化 `shared_ptr`，`weak_ptr` 仍停留在原理说明。建议补充：

- 同时保存强、弱计数的控制块；
- `WeakPtr` 的拷贝、移动和析构；
- `expired()` 和 `lock()`；
- 强计数归零时销毁对象；
- 强计数和弱计数都归零时销毁控制块；
- 说明教学版本为什么不能完整模拟标准库的线程安全保证。

### 2.2 Day306：补全红黑树的对称分支和删除修复

当前实现省略了插入修复的镜像分支、删除以及删除修复。建议至少补充：

- `rotate_right`；
- 完整的左右镜像插入修复；
- 查找、插入和中序迭代；
- 删除节点的结构替换；
- 双黑修复的主要情况；
- 红黑树不变量验证函数。

如果不准备补完整，应把题名明确改成“红黑树插入原理与核心旋转”，避免标题超过实际实现范围。

### 2.3 Day300：区分类型擦除版与 SBO 版

当前 `Function` 已完成类型擦除和深拷贝，但没有真正实现 SBO。可以选择：

1. 保留当前教学版，并把 SBO 明确列为追问；
2. 再增加一个固定内部缓冲区版本，讨论大小、对齐、移动和析构函数表。

### 2.4 整理分散的 Untitled 文件

部分旧题的正文被拆在 `Untitled.md`、`Untitled 1.md` 等文件中。建议在不破坏图片引用的前提下合并到主文档，至少为辅助文档改成可搜索的名称。

## 3. 第一优先级：建议正式加入专题

这些题用于填补知识结构中的明显空洞。其中前 10 题里的首批 8 题已经以 Day322～Day329 落地，拓扑排序、Dijkstra、SpinLock 和 Semaphore 留待后续批次。

| 顺序 | 建议题目 | 最小实现范围 | 主要考点 |
|---:|---|---|---|
| 1 | 实现二叉树遍历 | 前序、中序、后序、层序的递归与迭代 | 栈、队列、访问顺序、空树 |
| 2 | 实现二叉搜索树 | 查找、插入、删除 | 前驱后继、三类删除、退化 |
| 3 | 实现 Trie 字典树 | 插入、查找、前缀匹配、删除 | 字符映射、节点所有权、空间成本 |
| 4 | 实现 LFU Cache | 哈希表加频次链表 | `O(1)` 操作、最小频次、同频 LRU |
| 5 | 实现简化版 `variant` | 原地存储两个或少量候选类型 | 判别联合、生命周期、访问检查 |
| 6 | 实现并查集 | 路径压缩、按秩或按大小合并 | 近常数复杂度、连通性 |
| 7 | 实现图的 BFS 和 DFS | 邻接表、递归与迭代遍历 | visited、非连通图、复杂度 |
| 8 | 实现拓扑排序 | Kahn 算法和环检测 | 入度、DAG、依赖调度 |
| 9 | 实现 Dijkstra | 邻接表加小根堆 | 松弛、过期堆元素、负权限制 |
| 10 | 实现 Bitmap | 设置、清除、测试、计数 | 位运算、边界、空间压缩 |
| 11 | 实现 SpinLock | `atomic_flag` 最小版本 | acquire/release、忙等、退避 |
| 12 | 实现 Semaphore | 互斥锁加条件变量版本 | 计数资源、虚假唤醒、关闭语义 |

推荐学习顺序：

```text
二叉树遍历 -> 二叉搜索树 -> Trie
-> 并查集 -> BFS/DFS -> 拓扑排序 -> Dijkstra
-> LFU -> Bitmap -> variant
-> SpinLock -> Semaphore
```

这里把树遍历、BST、图遍历、拓扑排序和最短路拆开，是因为它们分别可以成为一道独立面试题，不建议合并成一篇“树和图大全”。

## 4. 第二优先级：Linux 后台方向建议加入

这些题不一定是所有 C++ 岗位的必考题，但和当前线程池、定时器、Reactor 的学习链非常匹配。

| 建议题目 | 最小实现范围 | 关键追问 |
|---|---|---|
| 实现 Bloom Filter | Bitmap 加多哈希 | 为什么有假阳性、没有假阴性；参数如何选择 |
| 实现一致性哈希 | 哈希环加虚拟节点 | 节点增删时迁移多少数据；如何处理倾斜 |
| 实现令牌桶限流器 | 容量、补充速率、时间戳 | 突发流量、时钟选择、并发保护 |
| 实现漏桶限流器 | 固定流出速率和等待队列 | 与令牌桶的区别、排队和丢弃策略 |
| 实现通用连接池 | acquire、release、超时和关闭 | RAII 归还、失效连接、容量上限 |
| 实现异步日志队列 | 前端写入、后台落盘、批量刷新 | 队列满策略、日志丢失、优雅退出 |
| 实现网络 Buffer | 可读可写区域、扩容、回收 | 半包、粘包、指针失效、零拷贝边界 |
| 实现长度字段协议解析器 | 包头、包长、消息体状态机 | 非法长度、半包、多包、攻击输入 |

这组题的推荐顺序是：

```text
Bitmap -> Bloom Filter -> 一致性哈希
-> 令牌桶/漏桶 -> 连接池
-> Buffer -> 协议解析 -> 异步日志
```

令牌桶和漏桶可以放在同一个 Day 中对比；Buffer 和协议解析应拆为两个独立题目。

## 5. 第三优先级：C++ 资源管理与容器进阶

| 建议题目 | 价值 | 建议范围 |
|---|---|---|
| 实现 `scope_guard` | 小而精，直接考 RAII 和异常路径 | 移动、dismiss、析构 `noexcept` |
| 实现 `enable_shared_from_this` 原理版 | 衔接 Day111 | 内置弱引用、初始化时机、重复控制块 |
| 实现侵入式链表 | 适合内核和嵌入式方向 | hook、对象生命周期、无额外节点分配 |
| 实现固定容量 `static_vector` | 适合嵌入式和实时系统 | 原地存储、容量上限、对象生命周期 |
| 实现 SmallVector | 衔接 vector 和 SBO | 栈内缓冲、迁移到堆、异常安全 |
| 实现字符串 SSO | 深化现有 `string` | 短串状态、长串状态、切换和移动 |
| 实现 B/B+ 树核心节点 | 数据库和存储方向 | 分裂、合并、扇出、范围查询 |
| 实现简化 JSON 解析器 | 综合代码题 | tokenizer、递归下降、错误位置 |

其中 `scope_guard`、侵入式链表和 `static_vector` 很适合嵌入式 C++；B+ 树和 JSON 解析器代码量较大，不应列为通用必背题。

## 6. 第四优先级：高阶并发挑战

这些题应明确标记为高阶，不要和基础手写题使用同一验收标准。

1. 无锁栈：CAS 循环、ABA 问题、内存回收。
2. MPMC 有界无锁队列：序号槽位、多生产者多消费者竞争。
3. Hazard Pointer：线程注册、退休链表、安全回收。
4. Epoch Based Reclamation：读侧临界区和延迟回收。
5. Work Stealing 线程池：本地队列、窃取、停止协议。
6. 协程 `Task` 和调度器：promise、awaiter、continuation、生命周期。
7. 分层时间轮：级联、跨层迁移、时间跳跃。

高阶无锁题真正的难点通常不是 CAS 本身，而是对象生命周期和安全回收。没有说明 ABA 与内存回收的“无锁栈实现”，不能算完整答案。

## 7. 不建议为了数量单独新增的题

下面这些内容可以作为现有题目的追问或练习，不必都创建 Day 目录：

- `strcat`、`strchr`、`memset`、`memcmp`：可并入字符串和内存函数复习；
- 冒泡、选择、插入排序：可并入排序基础，不必逐个建立目录；
- 用两个栈实现队列、用两个队列实现栈：适合作为 Day307 追问；
- 删除倒数第 K 个节点、链表分区等 LeetCode 变体：适合算法题单，不适合无限扩张本专题；
- 手写 `make_unique`：实现太短，可放在 `unique_ptr` 追问；
- 单独手写 `pair`：考察维度有限，可放到模板或 STL 专题；
- 纯 epoll API 示例：应进入 Linux 后台专题；只有封装成 Buffer、协议解析器或事件循环组件时才进入手写专题。

## 8. 建议的扩展规模

不建议一次把所有候选题都建成目录。比较合理的目标是：

```text
当前 46 个目录
+ 第一优先级 12 题
+ 后台方向精选 6 题
+ 资源管理/嵌入式精选 4 题
= 约 68 个目录
```

到 65～70 个高质量主题后，继续增加数量的收益会明显下降。此时应优先：

1. 补齐现有标题承诺的实现；
2. 给代码增加边界测试；
3. 验证异常安全和线程退出路径；
4. 统一主文档名称；
5. 维护推荐学习顺序和跨专题链接。
