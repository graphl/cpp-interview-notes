# C++ 面试题：实现读写锁

## 1. 考点

读写锁允许多个读者并发访问，但写者必须独占。它适合读多写少且临界区有一定工作量的场景。

面试主要考：

1. 互斥锁和条件变量
2. 读者数量
3. 写者互斥
4. 公平性与饥饿
5. RAII 锁守卫

---

## 2. 写者优先实现

```cpp
#include <condition_variable>
#include <mutex>

class ReadWriteLock {
public:
    void lock_shared() {
        std::unique_lock<std::mutex> lock(mtx_);
        readers_cv_.wait(lock, [this] {
            return !writer_active_ && waiting_writers_ == 0;
        });
        ++active_readers_;
    }

    void unlock_shared() {
        std::lock_guard<std::mutex> lock(mtx_);
        if (--active_readers_ == 0) {
            writers_cv_.notify_one();
        }
    }

    void lock() {
        std::unique_lock<std::mutex> lock(mtx_);
        ++waiting_writers_;
        writers_cv_.wait(lock, [this] {
            return !writer_active_ && active_readers_ == 0;
        });
        --waiting_writers_;
        writer_active_ = true;
    }

    void unlock() {
        std::lock_guard<std::mutex> lock(mtx_);
        writer_active_ = false;
        if (waiting_writers_ > 0) {
            writers_cv_.notify_one();
        } else {
            readers_cv_.notify_all();
        }
    }

private:
    std::mutex mtx_;
    std::condition_variable readers_cv_;
    std::condition_variable writers_cv_;
    unsigned active_readers_ = 0;
    unsigned waiting_writers_ = 0;
    bool writer_active_ = false;
};
```

实际使用应通过 RAII 包装 `lock/unlock`，避免异常或提前返回导致永久不解锁。标准库已提供 `std::shared_mutex`、`std::shared_lock` 和 `std::unique_lock`。

---

## 3. 状态不变量

任意时刻必须满足：

1. `writer_active_ == true` 时，`active_readers_ == 0`
2. 写者只能有一个
3. 读者可以有多个，但必须没有活动写者
4. 有写者等待时阻止新读者进入，避免写者一直饥饿

---

## 4. 为什么使用两个条件变量？

读者通常要批量唤醒，写者只能唤醒一个。拆分条件变量能明确唤醒对象，并减少无意义的竞争。`wait` 必须使用谓词处理虚假唤醒。

---

## 5. 公平性和局限

这个版本是写者优先：只要有写者等待，新读者就不再进入。它避免写者饥饿，但写请求持续到来时读者可能饥饿。严格公平锁需要排队或阶段切换，设计会更复杂。

还要注意：

1. 不支持递归加锁
2. 不支持安全地从读锁直接升级为写锁
3. 错误线程解锁、重复解锁属于未定义用法
4. 读临界区很短时，普通互斥锁可能更快

---

## 6. 面试回答

读写锁用一个互斥锁保护内部状态，用读者数和写者活动标志决定谁能进入。读者在没有活动写者时可并发进入，写者必须等待所有读者退出并独占访问。为了避免写者饥饿，可以在有写者等待时阻止新读者进入，但这又可能造成读者饥饿，因此公平策略需要结合业务选择。
