# C++ 面试题：实现最小堆定时器

## 1. 考点

定时器常用于后台服务中处理超时任务，比如连接超时、请求超时、心跳检测。
手写定时器时，最常见的方案是最小堆。

面试主要考：

1. 定时任务的数据结构
2. 最小堆
3. 超时时间排序
4. 添加定时任务
5. 执行过期任务
6. 取消定时任务的处理方式

---

## 2. 最小堆实现

```cpp
#include <chrono>
#include <functional>
#include <queue>
#include <unordered_set>

class Timer {
public:
    using Clock = std::chrono::steady_clock;
    using Callback = std::function<void()>;

    size_t add(int timeout_ms, Callback cb) {
        size_t id = ++next_id_;
        TimerNode node;
        node.id = id;
        node.expire = Clock::now() + std::chrono::milliseconds(timeout_ms);
        node.cb = std::move(cb);
        heap_.push(std::move(node));
        return id;
    }

    void cancel(size_t id) {
        canceled_.insert(id);
    }

    void tick() {
        auto now = Clock::now();

        while (!heap_.empty()) {
            const TimerNode& node = heap_.top();

            if (node.expire > now) {
                break;
            }

            TimerNode current = node;
            heap_.pop();

            if (canceled_.erase(current.id) > 0) {
                continue;
            }

            current.cb();
        }
    }

private:
    struct TimerNode {
        size_t id;
        Clock::time_point expire;
        Callback cb;

        bool operator<(const TimerNode& other) const {
            return expire > other.expire;
        }
    };

    std::priority_queue<TimerNode> heap_;
    std::unordered_set<size_t> canceled_;
    size_t next_id_ = 0;
};
```

---

## 3. 为什么用最小堆？

定时器每次最关心的是“最近要过期的任务”。

最小堆可以保证堆顶就是最早过期的任务：

1. 添加任务：O(log n)
2. 取出最近过期任务：O(log n)
3. 查看最近过期任务：O(1)

这比每次遍历所有定时任务更高效。

---

## 4. 取消任务怎么处理？

`std::priority_queue` 不支持从堆中间高效删除元素。
所以常见简化做法是“惰性删除”：

1. 取消任务时，只把任务 id 放入 `canceled_`
2. 等任务到达堆顶时，再判断它是否被取消
3. 如果被取消，就直接丢弃

这种方式实现简单，适合面试手写。

---

## 5. 注意点

1. 推荐使用 `std::chrono::steady_clock`，避免系统时间调整影响定时器
2. 回调函数不要在持锁状态下执行，否则可能造成死锁或长时间阻塞
3. 取消任务可以用惰性删除
4. 如果需要更新任务时间，可以取消旧任务再添加新任务
5. 多线程环境下需要加锁保护堆和取消集合
6. 大量取消任务时，惰性删除可能导致堆里残留较多无效节点

---

## 6. 面试回答

最小堆定时器的核心是把每个定时任务按照过期时间放入最小堆，堆顶永远是最早过期的任务。每次 `tick` 时检查堆顶，如果已经过期，就取出来执行回调；如果还没过期，后面的任务也不用看。添加任务复杂度是 O(log n)，获取最近过期任务是 O(1)。取消任务可以用惰性删除，因为堆不适合从中间删除元素。
