# C++ 面试题：异常对象与栈展开

## 1. throw 之后发生什么

```text
构造异常对象
  -> 沿调用栈寻找匹配的 handler
  -> 逐层销毁已经构造完成的自动对象
  -> 进入匹配的 catch
  -> catch 结束后销毁异常对象
```

“寻找处理器”和“清理栈帧”在 ABI 中可能分阶段实现，具体机制依赖平台；C++ 语义上必须保证离开作用域的已构造自动对象被正确析构。

## 2. RAII 为什么能防止资源泄漏

```cpp
#include <fstream>
#include <stdexcept>
#include <vector>

void process() {
    std::ifstream file("input.txt");
    std::vector<int> values(100);

    throw std::runtime_error("failed");
}
```

异常离开 `process` 时，`values` 和 `file` 都会析构，因此动态内存和文件描述符随对象释放。裸资源如果没有绑定到析构函数，就不会自动获得这种保证。

## 3. 哪些析构函数会执行

```cpp
struct Member {
    Member(int id);
    ~Member();
};

struct Object {
    Member first{1};
    Member second{2}; // 假设这里构造时抛异常
    Member third{3};
};
```

结果：

1. `first` 已完成构造，因此会析构。
2. `second` 没有完成构造，不调用它的析构函数。
3. `third` 尚未开始构造。
4. `Object` 整体没有完成构造，因此不调用 `Object::~Object()`。

这也是资源应该放进成员 RAII 对象，而不是依赖最外层析构函数手工清理的原因。

## 4. 捕获和重新抛出

```cpp
try {
    work();
} catch (const std::exception& error) {
    log(error.what());
    throw; // 保留原异常对象和动态类型
}
```

使用 `throw error;` 会按表达式类型重新复制一个异常对象，可能发生切片。异常通常按 `const&` 捕获，以保留多态类型并避免不必要复制。

## 5. 析构函数为什么不能逃出异常

栈展开期间如果某个析构函数再次让异常逃出，系统同时存在两个活动异常，程序会调用 `std::terminate()`。析构函数通常应为 `noexcept`，需要报告的失败应通过显式 `close/commit` 操作在正常控制流中处理。

## 6. 面试口述版

抛出异常后，运行时寻找匹配的 catch，并在传播路径上逆序析构已经完成构造的自动对象，这就是栈展开。未完成构造的对象本身不析构，但其已构造成员会析构。RAII 利用这条规则保证资源释放。异常应按 const 引用捕获，重新抛出用单独的 throw，析构函数不能让第二个异常逃出栈展开过程。
