## 如何避免死锁？

### 统一加锁顺序

所有线程都按相同顺序加锁：

```text
先锁 user_mutex
再锁 order_mutex
再锁 log_mutex
```

不能有的地方反过来。

###  多把锁使用 std::lock / std::scoped_lock

```cpp
std::scoped_lock lock(mtx1, mtx2);
```

比手动：

```cpp
mtx1.lock();
mtx2.lock();
```

更安全。

---

### 缩小临界区

错误：

```cpp
std::lock_guard<std::mutex> lock(mtx);
read_file();
send_network();
update_state();
```

正确：

```cpp
Data data;
{
    std::lock_guard<std::mutex> lock(mtx);
    data = shared_data;
}

send_network(data);
```

持锁时间越长，死锁和性能问题越容易出现。

---

### 持锁时不要调用外部代码

危险操作：

```text
持锁调用 callback
持锁调用 virtual function
持锁调用日志模块
持锁发送网络请求
持锁执行阻塞 IO
持锁 join 线程
```

因为你不知道外部代码里面会不会再拿别的锁。

---

### 使用 try_lock 或超时锁

```cpp
if (mtx.try_lock()) {
    // do something
    mtx.unlock();
}
```

超时锁：

```cpp
std::timed_mutex mtx;

if (mtx.try_lock_for(std::chrono::milliseconds(100))) {
    // do something
    mtx.unlock();
}
```

适合：

```text
不能无限等待的业务
需要降级处理的场景
需要打印告警的场景
```
