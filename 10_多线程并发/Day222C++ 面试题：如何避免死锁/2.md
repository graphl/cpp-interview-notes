## 实际场景 2：日志模块和业务模块互相调用

### 错误场景

```text
业务线程：
  拿 business_mutex
    -> 调用 log()
      -> 等 log_mutex

日志线程：
  拿 log_mutex
    -> 回调业务状态
      -> 等 business_mutex
```

形成：

```text
business_mutex -> log_mutex
log_mutex -> business_mutex
```

这类死锁非常常见，因为代码看起来不像“锁顺序反了”，而是隐藏在函数调用里。

###  避免方式

1. 持锁时不要调用外部模块
2. 持锁时不要调用回调函数
3. 先复制数据，释放锁后再调用日志或回调

示例：

```cpp
std::string snapshot;
{
    std::lock_guard<std::mutex> lock(business_mutex);
    snapshot = build_status_locked();
}

log(snapshot);
```

##  实际场景 3：持锁等待条件变量或线程结束

###  join 导致死锁

```cpp
std::mutex mtx;
std::thread worker;

void stop() {
    std::lock_guard<std::mutex> lock(mtx);
    worker.join();
}
```

如果 worker 退出前也需要拿 `mtx`：

```text
主线程拿着 mtx，等待 worker 结束
worker 等待 mtx，无法结束
```

死锁。

### 正确思路

```cpp
void stop() {
    {
        std::lock_guard<std::mutex> lock(mtx);
        stopping = true;
    }

    cv.notify_all();

    if (worker.joinable()) {
        worker.join();
    }
}
```

原则：

```text
不要持锁 join
不要持锁等待耗时操作
不要持锁等待另一个线程完成
```
