## 🔹 什么是虚假唤醒

条件变量的 `wait()` 有可能**在没有收到 `notify` 的情况下就被唤醒**。
 也就是说，线程可能被“莫名其妙”地唤醒一次。

这就是所谓的 **虚假唤醒**。

------

## 🔹 为什么会虚假唤醒

1. **实现层面**
   - POSIX 标准（pthread_cond_wait）和 C++ 标准都允许库实现为了效率，可能“假装唤醒”。
   - 一般是操作系统或硬件层面做了优化，唤醒比严格保证“只唤醒一次”更容易实现。
   - 例子：Linux futex 机制里可能因为信号干扰、内核调度等，导致线程被唤醒。
2. **并发唤醒场景**
   - 多个线程都在等待条件时，`notify_one()` 可能会随机唤醒一个；
   - 但此时条件并没有满足，所以这个线程“被白唤醒”。

------

## 🔹 为什么要用 `while` 而不是 `if`

假设写成 **错误的方式**：

```
std::unique_lock<std::mutex> lock(mtx);
if (!ready) {  // 🚫 只检查一次
    cv.wait(lock);  // 被虚假唤醒后就往下执行了
}
// 这里 ready 可能还是 false，逻辑出错！
```

正确的方式：

```
std::unique_lock<std::mutex> lock(mtx);
while (!ready) {  // ✅ 循环检查条件
    cv.wait(lock);
}
// 能保证执行到这里时 ready 一定为 true
```

或者使用 C++11 的语法糖：

```
cv.wait(lock, []{ return ready; });
```

------

## 🔹 总结

- **虚假唤醒** = `wait()` 可能在没收到通知时也返回。
- 出现原因：操作系统/硬件优化、多个等待线程竞争等。
- **对策**：必须在循环里反复检查条件（`while`），不能用 `if`。
