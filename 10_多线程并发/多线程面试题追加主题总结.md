# 多线程面试题追加主题总结

## 1. 多线程题目怎么分析

每一道多线程面试题，都可以先从这几个角度拆：

1. 共享了什么资源
2. 有没有并发读写
3. 用什么同步手段
4. 对象生命周期是否安全
5. 线程退出流程是否可控
6. 性能和调试怎么考虑

不要一上来只背 API。多线程题的核心通常不是“这个函数怎么用”，而是资源、同步、生命周期、退出和排查。

---

## 2. 共享了什么资源

先判断多个线程是否访问同一个资源。

常见共享资源：

1. 全局变量
2. 堆对象
3. STL 容器
4. 文件描述符
5. socket
6. 日志队列
7. 单例对象
8. 线程池任务队列

如果是多个线程只读同一份数据，一般问题较少。
如果是一读一写或多写，就要考虑 data race。

---

## 3. 常见同步手段

根据场景选择同步工具：

| 工具 | 适合场景 |
|---|---|
| `std::mutex` | 保护普通临界区 |
| `std::shared_mutex` | 读多写少 |
| `std::condition_variable` | 等待某个条件成立 |
| `std::atomic` | 简单状态、计数、无锁标志 |
| `semaphore` | 控制资源数量 |
| `future/promise` | 线程间传递结果 |
| `call_once` | 一次性初始化 |

回答时要说明为什么选这个工具，而不是只说“加锁”。

---

## 4. 多线程中堆内存如何管理

核心结论：

```text
每个线程有自己的栈；
所有线程共享同一个进程地址空间；
堆内存是进程级资源，多个线程可以访问同一个堆对象。
```

典型风险：

```text
线程 A
  -> new 一个对象
  -> 把指针传给线程 B

线程 B
  -> 访问这个对象

线程 A
  -> delete 对象

线程 B
  -> 再次访问
  -> use-after-free
```

面试重点：

1. `malloc/free/new/delete` 本身通常是线程安全的
2. 分配器线程安全不等于堆对象线程安全
3. 多线程共享堆对象，需要保护对象内部状态
4. 跨线程传裸指针风险很高
5. 异步回调、线程池任务、`detach` 线程最容易出现悬空访问
6. 可以用 RAII、`shared_ptr`、`weak_ptr`、所有权转移、线程退出同步来管理生命周期

面试回答：

> 多线程中每个线程有独立栈，但共享同一个进程堆。堆分配器本身一般是线程安全的，所以多个线程同时 `malloc/free` 通常不会破坏分配器内部结构。但这不代表堆对象本身线程安全。如果多个线程访问同一个堆对象，需要用锁或原子保护对象状态；如果对象可能被某个线程释放，就要设计清楚所有权，比如使用 RAII、`shared_ptr/weak_ptr`，或者保证线程退出后再释放对象，避免 use-after-free。

## 5. 多线程中 signal 如何处理

注意区分两个概念：

| 名称 | 含义 |
|---|---|
| signal 信号 | Linux 异步通知机制，例如 `SIGINT`、`SIGTERM`、`SIGPIPE` |
| semaphore 信号量 | 同步工具，用来控制资源数量 |

多线程 signal 重点：

1. 信号处理函数是进程级设置的
2. 信号会递送给进程中的某个线程
3. 每个线程可以有自己的 signal mask
4. 推荐用专门线程处理信号
5. signal handler 里不能随便调用函数
6. 不要在 signal handler 里加锁、`malloc`、`printf`

推荐模型：

```text
主线程启动
  -> 屏蔽指定信号
  -> 创建工作线程
  -> 创建 signal 线程
  -> signal 线程 sigwait()
  -> 收到信号后通知主流程退出
```

面试回答：

> Linux 多线程程序中，信号处理函数是进程级注册的，但信号会递送到某个没有屏蔽该信号的线程。为了避免信号打断任意业务线程，工程里通常会让所有工作线程屏蔽信号，然后创建一个专门的信号线程，用 `sigwait` 同步等待信号。signal handler 中能做的事很少，因为很多函数不是异步信号安全的，通常只设置标志位，或者写 pipe/eventfd 通知主循环。

## 6. 多线程生命周期类题目

高频问题：

1. 多线程中如何避免 use-after-free
2. 多线程中对象生命周期如何设计
3. 回调捕获 `this` 为什么危险
4. `shared_ptr` 跨线程是否安全
5. `weak_ptr` 如何解决异步回调悬空问题
6. `detach` 为什么容易出问题
7. 线程池析构时如何停止所有线程

回答抓手：

```text
所有权
  -> 谁创建对象
  -> 谁持有对象
  -> 谁释放对象
  -> 线程退出前对象是否还活着
```

常见安全做法：

1. 不跨线程传裸指针
2. 需要共享生命周期时用 `shared_ptr`
3. 回调里用 `weak_ptr` 判断对象是否还活着
4. 析构时先通知线程退出，再 `join`
5. 队列关闭时唤醒所有等待线程
6. 线程池析构时停止接收任务，并等待工作线程退出

## 9. 总结

多线程面试题的本质不是单纯考 API，而是考：

```text
共享资源
  -> 同步方式
  -> 内存可见性
  -> 对象生命周期
  -> 线程退出
  -> 工程调试
```

回答时先说核心结论，再说具体机制，最后补充常见坑和项目里的处理方式。
