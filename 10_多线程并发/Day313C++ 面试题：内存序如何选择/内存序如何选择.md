# C++ 面试题：内存序如何选择

## 1. 原子不只保证“读写不可分割”

内存序还约束：当前线程的其他内存访问，何时对另一个线程可见。分析时需要同时区分：

1. 原子对象自身的修改顺序。
2. 编译器和 CPU 是否可以重排周围操作。
3. 两个线程之间是否建立 happens-before。

## 2. release/acquire 发布数据

```cpp
#include <atomic>
#include <cassert>

int payload = 0;
std::atomic<bool> ready{false};

void producer() {
    payload = 42;
    ready.store(true, std::memory_order_release);
}

void consumer() {
    while (!ready.load(std::memory_order_acquire)) {
    }
    assert(payload == 42);
}
```

当 acquire load 读到 release store 写入的值时：

```text
producer 写 payload
  -> release store ready
  -> acquire load ready
  -> consumer 读 payload
```

这条 synchronizes-with 关系让前面的普通写 happens-before 后面的普通读，因此 `payload` 不发生数据竞争。

## 3. 常见内存序

| 内存序 | 主要语义 | 常见场景 |
|---|---|---|
| `relaxed` | 只保证原子性和该原子的修改顺序 | 独立统计计数 |
| `release` | 此操作前的读写不能被移到发布之后 | 发布数据、解锁语义 |
| `acquire` | 此操作后的读写不能被移到获取之前 | 获取已发布数据、加锁语义 |
| `acq_rel` | 同时具有 acquire 和 release | 成功的读改写操作 |
| `seq_cst` | 额外提供所有顺序一致操作的单一全局顺序 | 默认、先保证正确性 |

`memory_order_consume` 长期缺乏可靠实现实践，面试和工程代码通常按 acquire 讨论。

## 4. relaxed 什么时候足够

```cpp
std::atomic<unsigned long> requests{0};

void record_request() {
    requests.fetch_add(1, std::memory_order_relaxed);
}
```

如果计数只要求最终数值正确，不用它发布其他数据，也不依赖它排序其他访问，relaxed 足够。relaxed 不是“完全没有顺序”，但不会为其他普通内存建立跨线程可见性保证。

## 5. 选择原则

1. 先用 mutex 或默认 `seq_cst` 写出正确版本。
2. 明确需要建立的 happens-before 边，再考虑 acquire/release。
3. 只有原子变量独立计数时才优先考虑 relaxed。
4. 不要仅凭 x86 上“测试没出错”证明弱内存序正确。
5. 无锁结构还要处理对象生命周期、ABA 和安全回收，内存序只是其中一部分。

## 6. 面试口述版

内存序决定原子操作与周围读写之间的排序和跨线程可见性。典型发布订阅中，生产者先写普通数据，再 release store 标志；消费者 acquire load 读到该标志后，生产者之前的写对消费者可见。relaxed 适合不承担发布作用的独立计数，复杂结构应先证明 happens-before 再削弱顺序。
