# C++ 面试题：火焰图怎么看

## 1. 这道题考什么？

火焰图用于把采样调用栈可视化，快速看出 CPU 热点和调用路径。

核心一句话：

> 火焰图看的是采样调用栈聚合后的宽度，越宽表示 CPU 消耗越多，不表示时间顺序。

---

## 2. 生成流程

常见流程：

```bash
perf record -F 99 -g -p <pid> -- sleep 30
perf script > out.perf
stackcollapse-perf.pl out.perf > out.folded
flamegraph.pl out.folded > flame.svg
```

也可以对程序运行采样：

```bash
perf record -F 99 -g ./app
```

---

## 3. 火焰图怎么看？

重点：

1. 横向宽度表示采样占比
2. 越宽说明 CPU 时间越多
3. 纵向表示调用栈深度
4. 上层是被调用函数
5. 下层是调用来源
6. 颜色通常没有性能含义，只是区分视觉

不要误解：

```text
火焰图横轴不是时间线。
左边不代表先发生，右边不代表后发生。
```

---

## 4. 什么样的火焰图值得优化？

优先看：

1. 很宽的业务函数
2. 很宽的 `memcpy`
3. 很宽的 `malloc/free`
4. 很宽的锁相关函数
5. 很宽的系统调用路径
6. 反复出现的重复调用链

判断：

| 图形特征 | 可能问题 |
|---|---|
| 顶部某函数很宽 | 当前函数自身很耗 CPU |
| 底部某路径很宽 | 某条业务路径整体很重 |
| `memcpy` 宽 | 数据拷贝多 |
| `malloc/free` 宽 | 频繁分配释放 |
| `futex` 宽 | 锁竞争或等待 |
| 内核路径宽 | 系统调用、网络、IO、驱动路径重 |

---

## 5. 分析例子

### 5.1 `memcpy` 很宽

说明：

```text
CPU 大量时间花在内存拷贝。
```

下一步：

1. 找调用 `memcpy` 的上层业务函数
2. 看是否重复拷贝
3. 是否可以 move、引用传递、零拷贝、复用 buffer

### 5.2 `malloc/free` 很宽

说明：

```text
频繁分配释放对象。
```

下一步：

1. 对象池
2. 预分配
3. 减少临时对象
4. 复用容器容量

### 5.3 `futex` 很宽

说明：

```text
可能有锁竞争、条件变量等待或线程同步开销。
```

下一步：

1. 用 GDB 看线程栈
2. 看锁粒度
3. 看是否线程数太多
4. 看是否任务队列设计不合理

---

## 6. 面试回答模板

> 火焰图是基于采样调用栈生成的，横向越宽表示 CPU 采样占比越高，纵向表示调用层次。看火焰图时，我会先找最宽的热点，再沿着调用栈往下看它从哪条业务路径来的。如果热点是业务函数，就优化算法；如果是 `memcpy`，说明拷贝多；如果是 `malloc/free`，说明分配释放频繁；如果是 `futex`，可能是锁竞争。火焰图不是时间线，不能把左右顺序理解成执行顺序。
