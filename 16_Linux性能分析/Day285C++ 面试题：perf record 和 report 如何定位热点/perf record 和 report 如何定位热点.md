# C++ 面试题：perf record 和 report 如何定位热点

## 1. 这道题考什么？

`perf record` 用来采样，`perf report` 用来分析采样结果。

它们适合回答：

```text
CPU 时间到底花在哪些函数上？
热点函数是从哪条调用路径来的？
热点在用户态还是内核态？
```

---

## 2. 常用命令

采样一个进程：

```bash
perf record -g -p <pid> -- sleep 10
perf report
```

运行并采样：

```bash
perf record -g ./app
perf report
```

指定采样频率：

```bash
perf record -F 99 -g -p <pid> -- sleep 30
```

---

## 3. 参数解释

| 参数 | 含义 |
|---|---|
| `record` | 记录采样数据 |
| `report` | 查看采样结果 |
| `-g` | 记录调用栈 |
| `-p <pid>` | 采样指定进程 |
| `-F 99` | 每秒采样约 99 次 |
| `-- sleep 10` | 采样 10 秒 |

建议编译：

```bash
g++ -O2 -g -fno-omit-frame-pointer main.cpp -o app
```

原因：

1. `-O2` 接近真实性能
2. `-g` 保留符号和源码信息
3. `-fno-omit-frame-pointer` 让调用栈更容易准确

---

## 4. report 怎么看？

重点看：

1. `Overhead`：采样占比
2. `Command`：进程名
3. `Shared Object`：热点来自主程序、动态库还是内核
4. `Symbol`：热点函数
5. 调用栈：热点是从哪里调用来的

典型解释：

| 热点 | 可能原因 |
|---|---|
| 业务函数 | 算法或循环热点 |
| `memcpy` | 数据拷贝多 |
| `malloc/free` | 频繁分配释放 |
| `futex` | 锁竞争或条件变量等待 |
| `copy_user` | 用户态/内核态拷贝多 |
| 网络协议栈函数 | 网络路径重 |
| 文件系统函数 | IO 路径重 |

---

## 5. 用户态和内核态热点

如果热点在用户态：

```text
优先看算法、数据结构、循环、内存拷贝、分配释放。
```

如果热点在内核态：

```text
优先看系统调用、网络、文件系统、驱动、中断、锁。
```

例子：

```text
热点在 tcp_sendmsg
```

可能说明发送路径开销高、小包太多、socket buffer 或网络栈压力大。

---

## 6. 常见坑

1. 不加 `-g`，报告里只有地址
2. 不记录调用栈，只看到单个函数，不知道来源
3. 采样时间太短，偶然性很强
4. workload 不稳定，前后对比不可信
5. 只看热点函数，不看调用路径
6. 把采样占比当作精确耗时

---

## 7. 面试回答模板

> 我会先用 `perf stat` 判断瓶颈类型，再用 `perf record -g` 采样调用栈，用 `perf report` 看热点函数和调用路径。看 report 时不只看函数名，还要看热点来自主程序、动态库还是内核。如果热点在业务函数，就分析算法和循环；如果在 `memcpy`，说明拷贝多；如果在 `malloc/free`，说明分配释放频繁；如果在 `futex`，可能是锁竞争。优化后要用同样 workload 再采样对比。
