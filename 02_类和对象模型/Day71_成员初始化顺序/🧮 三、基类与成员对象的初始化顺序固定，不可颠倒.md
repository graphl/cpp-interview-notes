## 🧮 三、基类与成员对象的初始化顺序固定，不可颠倒

**顺序规则：**

1. 先构造 **基类部分**
2. 再构造 **成员变量**
3. 最后执行 **派生类构造函数体**

------

### 🧩 示例：

```
class Base {
public:
    Base() { cout << "Base()\n"; }
};

class Member {
public:
    Member() { cout << "Member()\n"; }
};

class Derived : public Base {
    Member m;
public:
    Derived() { cout << "Derived()\n"; }
};
```

### 输出：

```
Base()
Member()
Derived()
```

📌 **总结：**

> 即使你在初始化列表里写 `Derived() : m(), Base() {}`, 依然会 **先构造 Base，再构造 m**。

## 🧩 四、在构造函数中调用虚函数是危险的 ❌

构造阶段多态尚未建立。

### 示例：

```
class Base {
public:
    Base() { foo(); }   // 在构造中调用虚函数
    virtual void foo() { cout << "Base::foo\n"; }
};

class Derived : public Base {
public:
    void foo() override { cout << "Derived::foo\n"; }
};
```

### 输出：

```
Base::foo
```

📌 **原因**：

> 构造 `Base` 时，对象的动态类型还只是 `Base`，
>  派生类部分尚未构造完成，多态机制尚未生效。

⚠️ **同理，析构函数中也不应调用虚函数。**

## 🧩 五、析构时成员的销毁顺序反向执行

这意味着：

> **如果成员 A 依赖成员 B 的存在，就要保证 A 在 B 之后构造。**

否则析构时会反向执行，导致 A 析构时使用了已销毁的 B。

### 🧩 示例（错误）：

```
class File {
public:
    void close() { cout << "关闭文件\n"; }
};

class Logger {
    File& f;
public:
    Logger(File& file) : f(file) {}
    ~Logger() { f.close(); }  // 假设记录关闭日志
};

class Manager {
    Logger log;
    File file;
public:
    Manager() : log(file) {}
};
```

⚠️ **错误原因：**

- `Manager` 构造时：
  1. 先构造 `log`
  2. 再构造 `file`
- 析构时反过来：
  1. 先析构 `file`
  2. 再析构 `log` → log 想访问 file，但 file 已销毁 ❌

📌 **解决办法：**

> 改变成员声明顺序：

```
class Manager {
    File file;
    Logger log;
public:
    Manager() : log(file) {}
};
```

## 🧩 六、静态对象之间的构造/析构顺序不确定（跨翻译单元）

跨 `.cpp` 文件的静态对象，**构造顺序未定义**，析构顺序也同样不可预测。

📌 **建议：**

> - 避免在全局或静态对象构造期间依赖其他静态对象；
> - 使用函数内静态对象（Meyers Singleton）保证安全初始化。

```
Singleton& instance() {
    static Singleton s; // 线程安全初始化
    return s;
}
```
